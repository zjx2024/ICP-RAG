# 知识图谱系统部署指南

本文档说明如何在**新机器**上部署知识图谱系统（含智能体平台模块）。

---

## 1. 系统架构

```
┌─────────────────────────────────────────────────────────┐
│                        宿主机                            │
│  ┌──────────────┐   ┌──────────────┐  ┌───────────────┐ │
│  │ knowledge-app │   │ 浏览器访问    │  │ 模型服务       │ │
│  │  FastAPI:9999 │◄─►│ :9999        │  │ (Ollama/云端) │ │
│  └──────┬───────┘   └──────────────┘  └───────────────┘ │
│         │ 容器内网 knowledge-network                     │
│  ┌──────┼─────────────────────────────────────────┐     │
│  │  postgres    :5432    (数据存储)                │     │
│  │  elasticsearch:9200   (向量检索)                │     │
│  │  minio       :9000    (对象存储)                │     │
│  │  hugegraph   :8081    (图数据库)                │     │
│  │  hubble      :18088   (图可视化)                │     │
│  └───────────────────────────────────────────────┘     │
└─────────────────────────────────────────────────────────┘
```

| 服务 | 端口 | 用途 |
|------|------|------|
| app | 9999 | FastAPI 主服务（含智能体） |
| postgres | 5432 | PostgreSQL：文档/任务/消息/模型配置 |
| elasticsearch | 9200 | 向量检索 |
| minio | 9000 | 图片/文件存储 |
| hugegraph | 8081 | 知识图谱存储 |
| hubble | 18088 | 图谱可视化 |

## 2. 前置条件

### 2.1 系统要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（本部署已适配 Ubuntu/CentOS） |
| Docker | 20.10+（推荐 28.x，含 Docker Compose v2） |
| git | 任意版本 |
| 内存 | ≥ 8GB（ES+HugeGraph+MinIO 常驻） |
| 磁盘 | ≥ 50GB 空闲 |
| 网络 | 首次构建需访问 Docker Hub / pip / npm |

### 2.2 安装 Docker

```bash
# Ubuntu/Debian
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 验证
docker --version          # Docker version 28.4.0
docker compose version    # Docker Compose version v2.39.4
```

> 若用户非 root，将用户加入 docker 组：`sudo usermod -aG docker $USER` 后重新登录。

## 3. 部署步骤

### 3.1 拉取代码

```bash
git clone <你的仓库地址> 知识图谱
cd 知识图谱
```

仓库包含部署所需的全部文件：

```
知识图谱/
├── app/                  # 后端源码（含 agent/ 智能体模块）
├── static/               # 前端页面（index/agent/gallery.html）
├── docker-compose.yml    # 服务编排
├── Dockerfile            # app 镜像构建
├── entrypoint.sh         # 容器启动入口
├── requirements.txt      # Python 依赖
├── start.sh              # 启动脚本
├── stop.sh               # 停止脚本
├── restart-app.sh        # 重启 app 脚本
├── export-images.sh      # 镜像导出/迁移打包脚本
├── volumes/              # 持久化数据目录（postgres/es/minio/hugegraph，随迁移包拷贝）
└── .gitignore
```

### 3.2 创建 .env 配置文件

`.env` 文件**不随 git 上传**（含密码，被 .gitignore 排除），需手动创建。

```bash
cp /path/to/模板 .env   # 或手动创建
```

`docs/部署指南.md` 建议的 .env 模板：

```env
# === 数据库 / 检索 / 存储（本地模式，容器内会被 compose 覆盖为容器主机名）===
ES_HOST=localhost
ES_PORT=9200
ES_USERNAME=
ES_PASSWORD=
ES_SCHEME=http

MINIO_ENDPOINT=localhost:9000
MINIO_ACCESS_KEY=admin
MINIO_SECRET_KEY=password
MINIO_SECURE=false

POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_USER=postgres
POSTGRES_PASSWORD=password
POSTGRES_DB=knowledge_graph

# === 模型配置已迁移到数据库 llm_models 表 ===
# 请在模型管理页面添加模型，以下仅保留运行时参数
MODEL_TEMPERATURE=0.7
MODEL_MAX_TOKENS=262144
MODEL_TIMEOUT=3000
MODEL_TOP_P=0.1

EMBEDDING_DIM=1024
CHUNK_SIZE=512
CHUNK_OVERLAP=50

HUGEGRAPH_HOST=localhost
HUGEGRAPH_PORT=8081
HUGEGRAPH_GRAPH_NAME=hugegraph

SERVER_HOST=0.0.0.0
SERVER_PORT=9999
# SERVER_IP 由 start.sh 自动检测写入，无需手动配置
```

> **安全建议**：生产环境请修改 `POSTGRES_PASSWORD` / `MINIO_SECRET_KEY` 为强密码，并同步修改 docker-compose.yml 中对应值（若 compose 内使用默认值）。

### 3.3 启动服务

```bash
./start.sh
```

start.sh 会自动：
1. 检测宿主机局域网 IP 写入 `.env`（`SERVER_IP`）
2. 执行 `docker compose up -d` 启动 6 个服务
3. 首次运行会自动构建 app 镜像（需联网拉取依赖）

**等待健康检查**（首次可能需要 1-3 分钟，ES/HugeGraph 初始化较慢）：

```bash
docker ps
```

期望输出：6 个容器全部 `Up`，postgres/es/minio/hugegraph 状态为 `(healthy)`。

### 3.4 验证部署

```bash
# 1) app 服务
curl -s http://localhost:9999/ -o /dev/null -w "%{http_code}\n"    # 期望 200

# 2) 各服务健康
curl -s http://localhost:5432        # postgres 有响应
curl -s http://localhost:9200/_cluster/health | head -1            # ES
curl -s http://localhost:8081/graphs/hugegraph                      # HugeGraph
curl -s http://localhost:9000/minio/health/live                     # MinIO
```

### 3.5 配置模型（必须）

> **模型全部从数据库 `llm_models` 表读取，不走 .env / config 文件**。新机器数据库为空，必须重新配置，否则解析/生成图谱/智能体对话都会报"未配置模型"错误。

1. 浏览器打开 `http://<新机器IP>:9999`
2. 进入**模型管理**页面
3. 添加**对话模型**（类型 `llm`）：
   - **Ollama 本地**：provider=`ollama`，base_url=`http://<Ollama所在机器IP>:11434`，model=`qwen3.6:latest`（或其他已下载模型）
   - **阿里云 Qwen**：provider=`qwen`，填写 API Key、url、model
4. 添加 **Embedding 模型**（如 `bge-m3:latest`，provider=`ollama`）
5. 分别标记一个默认模型（llm 类型 + embedding 类型）

### 3.6 创建智能体

智能体创建时需从 `llm_models` 表选择对话模型和 embedding 模型，绑定到 `agent_models` 表（含 plan/reflect/answer/embedding 角色）。

## 4. 常用运维操作

| 操作 | 命令 | 说明 |
|------|------|------|
| 启动全部 | `./start.sh` | 镜像存在直接启动 |
| 停止全部 | `./stop.sh` | `docker compose down` |
| 重启 app（改代码） | `./restart-app.sh` | 只重建 app，不影响其他服务 |
| 查看状态 | `./start.sh ps` | 容器状态 |
| 查看日志 | `docker logs -f knowledge-app` | 跟踪 app 日志 |
| 重建镜像 | `./start.sh up -d --build` | 强制重建 |

## 5. 代码更新

代码已打进镜像（Dockerfile `COPY . .`），**无 bind mount**，修改代码后需重建镜像：

```bash
./restart-app.sh    # 重建 app 镜像并重启（改 app/ static/ requirements 后通用）
```

## 6. 数据持久化与迁移

### 6.1 数据目录（Dify 式外部挂载）

所有持久化数据存放于项目根目录 **`volumes/`**（外部挂载目录，不再是 Docker 具名卷），拷贝目录即可完成数据迁移：

| 服务 | 挂载目录 | 数据 |
|------|---------|------|
| postgres | `./volumes/postgres` | 数据库全部数据 |
| elasticsearch | `./volumes/es` | 索引数据 |
| minio | `./volumes/minio` | 图片/文件 |
| hugegraph | `./volumes/hugegraph` | 图谱实体/关系 |

> **⚠️ 权限注意**：ES 容器内以 uid `1000` 运行、postgres 以 uid `999` 运行。从旧机器迁移卷数据后，必须修复目录属主，否则容器无法读写：
>
> ```bash
> docker run --rm -v "$PWD/volumes/es":/data alpine chown -R 1000:1000 /data
> docker run --rm -v "$PWD/volumes/postgres":/data alpine chown -R 999:999 /data
> ```

> **⚠️ HugeGraph 挂载点修复**：数据目录必须挂到 `/hugegraph-server/rocksdb-data`（镜像真实 VOLUME 点）。旧配置挂 `/graphdata` 无效，会导致容器重建后数据"丢失"（实际落在匿名卷）。当前 docker-compose.yml 已修复。

### 6.2 一键导出迁移包

```bash
./export-images.sh    # 导出 6 个镜像 tar 到 images/，见脚本提示
```

迁移包内容：
```
images/                    # 6 个镜像 tar（app/postgres/es/minio/hugegraph/hubble）
volumes/                   # 全部持久化数据
docker-compose.yml         # 编排配置
.env                       # 环境变量（含密码，注意安全）
start.sh / stop.sh / restart-app.sh / entrypoint.sh
```

### 6.3 新机器恢复（Dify 式移植）

```bash
# 1. 加载镜像（逐个）
gunzip -c images/knowledge-graph-app.tar.gz | docker load
gunzip -c images/postgres.tar.gz | docker load
# ... 其余镜像同理

# 2. 拷贝迁移包到目标目录，确认 volumes/ 结构完整

# 3. 修复数据权限（关键！ES/postgres）
docker run --rm -v "$PWD/volumes/es":/data alpine chown -R 1000:1000 /data
docker run --rm -v "$PWD/volumes/postgres":/data alpine chown -R 999:999 /data

# 4. 启动
./start.sh    # 自动检测 IP，启动全部服务

# 5. 验证
docker ps     # 6 容器全部 Up + healthy
curl http://localhost:9999
```

模型配置（`llm_models`/`agent_models` 表）在 `volumes/postgres` 内，随数据迁移自动恢复，**无需重新配置模型**。

## 7. 常见问题排查

### 7.1 服务无法启动

```bash
docker compose -p knowledge-graph ps          # 看状态
docker compose -p knowledge-graph logs app    # 看 app 日志
```

### 7.2 提示"未配置模型" / 模型调用失败

- 检查 `llm_models` 表是否有对应类型模型（`llm`/`embedding`）
- Ollama 模型需先在新机器 `ollama pull qwen3.6:latest` 等
- 检查 base_url 从 app 容器内能否访问：`docker exec knowledge-app curl http://<IP>:11434`

### 7.3 端口被占用

```bash
sudo lsof -i :9999   # 或 ss -tlnp
```

### 7.4 前端页面改了什么不生效

代码已打进镜像，无 bind mount。修改 `static/` 后需重建镜像并重启：

```bash
./restart-app.sh
```

### 7.5 局域网其他机器访问

- 确认 start.sh 检测的 `SERVER_IP` 正确（`cat .env | grep SERVER_IP`）
- 确保宿主机防火墙放行 9999 端口
