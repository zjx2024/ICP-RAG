# R3b：正文审核职责替换

2026-09-06。基线为 `.artifacts/evals/architecture-20260906/source-r3a-before-r3b.tar.gz`，不是分支 HEAD；既有工作区改动保留。本记录不代表整体质量验收。

## 职责变化

生产链收敛为初稿一次调用、综合审核/必要修订一次调用、机械验证、纯引用发布。审核同时处理当前分问、对象与记录、来源归属、条件/影响/次序和安全；字段只作为证据，不再决定回答栏目。没有为具体测试 ID 或用户问法新增分支。

本批删除四个 `answer_domain_{fault,history,target,calculation}` 模块、`answer_completion.py` 和 `answer_editor_budget.py`；删除 `answer.py` 中旧引用校核、开放断言编辑、两轮 closure、墙句恢复、终点补写/去重/删改、字段交付判定及兼容导出。现有证据选择/字段投影模块仍服务检索，留给 R4 按职责检查，不恢复正文编辑用途。

`answer_review.py` 是有界纯协议校验器，不依赖答案编排或存储。自然语言完成度和断言含义由模型判断；代码验证完整 JSON、逐单元来源字段/字面引文、精确记录与代码、来源归属、计算授权和禁止的断言类别。问题措辞不需要命中某几个固定词。

审核预算独立于初稿的 1200 token：上限 8192 token、180 秒传输/节点预算、无内部重试。无法完整解析、未知/错源绑定、正文单元未关联本轮目标等都使本次明确失败，不回填草稿。部分可答必须有真实查询/缺口观察支持；仅有免责声明或澄清不记为完整回答。

新交付清单只写自然语言 `goal_delivery` 及实际证据身份。保留 API 字段名和历史字段清单的读取兼容，但不再用旧字段目录判定本轮“已答”。R4 需接续检查会话消费者。

## 测试迁移纪律

原 1622 项中，281 项依赖退役的串行编辑、固定字段完成、词语补写/救回或编辑预算行为，同批退役；新入口增加 57 项测试，覆盖协议、身份、来源、非事实来源隔离、数值授权、SSE、单次审核、错误不回填和发布保真。来源读取、图重授权、FTA/RBD 算法和 Dify 等未因删除编辑器而删除实现。

清单见 `.artifacts/evals/architecture-20260906/r3b-test-migration-final.json`。旧源码和测试均可从基线快照恢复。测试数量变化不代表质量进退，也不能把新旧不同协议的测试数量当作等价覆盖证明；语义有效性仍由冻结多轮和留出集验收。

## 工程检查与诊断

- 后端全量测试当前 1398 项通过，27.508 秒；compileall、Ruff 关键错误和 diff 检查通过。后端净减 9502 行；`answer.py` 为 950 行，主节点 82 行，审核协议 395 行。增删细目见 `r3b-observations.json`。
- 前端 npm ci、10 项协议测试和生产构建通过，构建 5.39 秒。Dify 原 server-info 路由真实响应正常；本批未改上传、图片证据或 Dify 检索实现。
- 首次冒烟保存了三次协议拒绝，随后主动中断，不能算八轮完整运行。以冻结初稿单独探查审核发现：单元漏绑提及的父记录、额外单元未关联目标、来源归属 basis 不是正文原话。未放宽验证；补充通用协议说明和私有审核提案/拒绝原因观测。探查不是原调用重现，也不是质量评测。
- 新的八轮固定历史重放已在 `capture-r3b-reviewed-new-model/` 完成：1 轮发布、7 轮拒发。拒发原因是四轮单元未关联目标、一轮错记录绑定、两轮未绑定精确身份；没有 JSON 解析失败。八对已记录生成状态/上下文/模型参数与 R3a 相同。调用 73→45、中位耗时 78.62→48.98 秒，但大量拒发使这组延迟不能代表正常完整回答的提速；整体可用性与质量未验收。唯一发布稿经过编号仍正文保真。不把运行错误隐藏成正常答案，也不运行新裁判或全量质量门槛来阻挡 R4。
- 八轮结束后另加强数值原样转述校验：按完整数值等值验证，不能靠小数前缀通过，等值科学记数法可接受；补充 FTA 割集授权不能升级为概率授权的回归。另补齐本地观测中的计算请求/来源关系字段。这些纯校验/观测改动经过最终离线测试，未再次运行八轮；最终源指纹为 `after-r3b-new-model.json`，不冒充最终版全量真实验收。

## R4 已定位的工作

1. 已选中正确历史引用，但查询仍走多字段 OR 关键词检索、按更新时间取前 N 条，目标旧案例可能根本未进入证据登记。应按通用的文档/业务记录/版本身份回 PG 重读，不能给某个案例编号增加例外。
2. HMC、FMECA、RBD 的会话重读路径不一致，MFL/历史缺少同等的精确引用入口。统一身份读取须保留新问题/纠正优先、集合查询和比较的范围语义，不把某条旧引用当作完整集合。
3. 检查证据门禁之后重复选择、历史筛选和旧发布状态读分支；来源投影、未确认关联和原文不存在必须保持分离。
4. 让会话读取自然语言交付目标、用户观察和未决问题，仍只把实际引用身份作为重读锚点，不复用旧答案作为工程事实。
