## Gold 复核中的实质修正

| 原问题 | 修正依据/验收要求 |
|---|---|
| HIST-04 配置加载失败关联 FM-SYN-029 | 改为 FM-SYN-028；029 是逻辑时序裕度不足 |
| MAINT-02 只列 PSU-A 两个可上报故障 | 纳入 MFL-SYN-006：不可直接上报，不得复制 004/005 的 API |
| BCM 复位、NGW 链路抖动等借同模块 API | 按 MFL 当前行区分“否/名称缺失”与“调用说明有文字”；后者不能证明接口可用 |
| FLS 索引损坏与空间满的维修差异 | FMECA 补偿字段可能相同，实际差异依据 MFL062 重建索引与 MFL063 受控回收/修正策略 |
| OOS-01 环境影响被强制范围外 | 允许澄清条件或依据资料解释温度/环境影响，仍不做天气预报或编环境限值 |
| OOS-08 未指定 RBD 模型却必须输出 0.99 | 允许能力说明、列候选/请求选模型，不强行计算 |
| “不显示”“通道有问题”等强制只澄清 | 接受有界候选检索加必要澄清，禁止无证据唯一诊断 |
| 满量程直接等同 A/D 故障 | 同时考虑饱和和线路开路；HIS020 是连接器针脚问题，不可串案 |
| RBD 显示十小时预期被疑为数据漂移 | 当前源仍为 0.99888052；保留正确预期，检查是否漏算/选错模型 |
| 系统核对必须回答“没有漏” | 按真实上轮答案判定，遗漏需承认并补正，允许必要复述 |
| HMC 与 MFL 按合成编号同序强制对应 | 源表没有显式编码关联列；必须区分未确认关联与没有 API，不强制声称 MFL001 属于该 HMC；独立同现象记录只能带未证实关联的限定 |

gold-v3 还统一要求：不能把父级职责归给子模块，不能把启动阶段流程扩成任何运行阶段全任务必停；合理澄清/无资料说明不因没有事实引用而单独判错。原 19 例与 100 例的非相邻回码问题同步修改，问题文字和用例身份不变。修改有源表结构与真实失败证据依据，不通过放松生产编码门禁来迎合原错误预期。

每轮以当前问题与源摘录核验对象、所问新维度、事实与引用。开放语义不以固定词汇正则评分；精确代码/指定记录仍可用确定性断言。计算要求正文和结构化结果同时匹配，不能靠工具“被调用过”或答案其他位置出现同一个数值放行。

## 源追溯与冻结

- `evals/icp_eval_gold_sources.json` 集中保存源文件 SHA-256 和 1-based 表格/行/段落坐标，避免各用例复制一套来源配置。
- 用例的 `metadata.gold_sources` 引用该索引；原始字段和空 API 值保留，不由被测智能体生成 gold。
- `scripts/eval_source_refs.py` 在加载用例时校验源指纹；文件变化、未知引用或无效坐标导致评测输入错误，不能静默更新正确答案。
- 裁判单独读取这些摘录及最终公开引用；**不把 gold、标准答案或源摘录放入被测会话请求**。
- 各轮明确区分一般可能原因、当前候选、历史已确认根因、案例复测结果和未记载参数。

## 执行与验收

```bash
.venv/bin/python -m scripts.audit_icp_eval_suite --strict-quality
.venv/bin/python -m scripts.calibrate_icp_judge --judge-timeout-seconds 120
.venv/bin/python scripts/capture_icp_eval_baseline.py -o .artifacts/evals/baseline.json
.venv/bin/python -m scripts.evaluate_icp_paraphrases evals/icp_multiturn_dialogue_cases.json --judge-timeout-seconds 120 -o .artifacts/evals/canary-19.json
```

先分析 19 例，再对三份 100 例文件分别运行同一评测器。正式复测应固定模型、代码、源文件及裁判配置，重复三次；期间改代码则另建版本，不混合成绩。运行异常与裁判异常单列，不能计作正常产品通过/失败；还须报告首轮/追问、题型和延迟分项。

2026-09-05 的裁判采用 qwen3.6:latest，与当时被测主模型相同但独立调用；当前项目默认已换为 Qwen3.8。2026-09-06 R5 使用相同 gold 校准两者，在有界 JSON Schema 传输下均为 34/36，仍有两个语义漏判，因此不能当作已合格的自动验收裁判。安全相关答案仍需复核证据链，校准失败不会被从报告中抹去。

R5 新增独立表达留出 8 例/24 轮，源数据仍是同一合成库，不冒充独立真实数据盲测。`run_icp_eval_campaign --acceptance --repeats 3 --judge-calibration <冻结报告>` 分别执行和报告 19/40、100/216 与 8/24；缺少或未合格的裁判校准只允许诊断，不允许把自动验收标为通过。见 [R4/R5 记录](ICP架构整改R4与R5记录.md)。
