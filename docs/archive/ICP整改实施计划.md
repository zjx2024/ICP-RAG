## 一、范围与原则

- 同时交付多轮回答修复、可维护的工程结构、能识别错答的评测以及可复现结果。
- 保留现有用户改动，不自动提交、推送或合并；按问题分批修改并记录验证。
- 七类知识入口、统一上传、Dify 两条路径、图片证据、PostgreSQL 权威事实不变。
- 模型理解开放语义；代码检查结构、身份、来源、授权、数值和资源边界。不以固定问句、特定词汇、测试 ID 或合成记录答案映射控制生产行为。
- 检索相关性与唯一身份分开：自然语言可以召回候选，跨文档身份/图关系必须由权威字段重新核验。模糊问题不能被强制唯一诊断，也不能一律拒绝。
- 用户本轮纠正优先于旧锚点；历史答案不是事实来源。已交付记录辅助组织答案，不禁止必要的复述、核对和纠错。
- `provisional` 不支持正式计算；人工确认不是 `auto_validated`，不扩展人工审核产品功能。
- 不通过删除失败用例、修改合理预期、放宽断言或隐藏基础设施错误获得绿灯。

## 三、各阶段实施清单

### 1A：先恢复可运行、可验证的基线

- 修复 `SequenceMatcher` 被调用却未导入；保留其仅用于召回相关性的边界。
- 对齐图投影测试替身与结果增量写入接口，验证已有解析统计不被覆盖。
- 核对 HMC 条件查询的唯一性探测、锚点重读、歧义字段与证据门禁之间的契约。
- 分类处理结构化实体、完整集合、历史案例等失败；记录合理产品预期和过时内部断言的区别。
- 增加静态未定义名称检查，避免“编译通过但执行 NameError”。

### 2：先校准尺子

- 黑盒质量与实现轨迹分开：使用了工具/字段不是回答正确；交付 manifest 不能自证内容已交付。
- 数值校验支持容差，但必须绑定对象和适用参数；分别验证正文和确定性工具结果，不能互相代替。
- 语义裁判读取当前问题、必要历史、最终答案和经过核验的标准；不信任被测系统自报完成。
- 固定裁判配置，记录是否与被测模型相同；用人工可判的好/坏答案校准。裁判不可用计为评测异常，不冒充产品错误或成功。
- 用错误身份、错配数值、遗漏新增维度、整段重答等反例测试评测器；加入等价自然表达正例。

### 3：100 例整改

- 原始基线三份共 100 例 / 200 轮，全部两轮；覆盖广度尚可，不能直接用于最终验收。现已补充为100例216轮，详见执行记录与测试集复核说明。
- 每个 gold 关联源文档、版本、记录身份与相关字段；区分明确事实、允许推断、缺失信息和合理澄清。
- 修正强制错误拒答、缺少对象仍强制出数值、用具体工具路线代替产品正确性等问题。
- 保留 100 个用例身份，按覆盖缺口扩展部分至 3～5 轮，另覆盖超过历史窗口的边界，不以固定总轮数为目标。
- 覆盖精确/部分代码、模糊/具体问题、相关/无关/无证据、澄清恢复、非相邻指代、话题切换返回、对象纠正、参数修正、近邻干扰、多对象比较与总结核对。
- 开放语义不再新增关键词正则；精确代码/API/业务 ID 和数值仍可确定性断言。
- 按来源和场景分组保留不参与调参的用例，注明这些资料已被开发者审阅，不声称是盲测或真实数据泛化证明。

### 1B：功能与检索修复

- 模型输出当前对象、本轮信息目标、显式授权、指代依据；代码统一校验，不按开放词汇加隐含义务。
- 当前用户纠正、选定证据身份、权威重读贯穿 plan → tools → gate → answer。
- HMC 完整/条件查询与 MFL 显式代码关联分开；邻居结果只作候选，不能混入当前报码结论。
- FMECA 原因/影响/检测对应同一权威行；历史条件、排查、结果与恢复验证绑定同一案例。
- RBD 自然问法可召回并选择有来源的模型候选；计算前核验身份、图等级、参数和用户授权。
- 回答围绕本轮问题综合，按证据区分已知、推断和未确认；允许核对时必要重复。
- 合并重复答案编辑职责，限制修复次数；内部清单回显、超时、无变化都需可观测退出。

### 4：工程结构与交付质量

- 先画出当前 import/数据依赖，再提取纯共享原语、显式数据契约和领域服务；禁止域模块反向导入 answer 编排入口。
- 不以行数减少作为验收；不把 75 个符号原样堆进一个新巨型模块。
- 合并相同语义的枚举与归一化；不同语义的别名不得强行合一。
- 建立状态字段写入者、读取者、跨轮保留、清空、兼容迁移表；旧 SSE/持久化字段先兼容再废弃。
- 关键存储错误上报；可选服务降级计数；观测系统故障不得拖垮主回答。
- 排序权重外置前补行为测试；避免同时改变排名策略和模块结构。
- 前端优先类型化关键 API/SSE 数据和统一上传交互；保持构建并增加关键交互回归，不扩大 UI 产品范围。
- PR CI：编译、静态错误检查、确定性后端测试、评测集结构校验、前端构建/关键测试。
- 独立真实评测任务：就绪预检、显式模型和数据、结果归档、错误分类；不把联网全量评测混进普通 unittest。

### 5：效果验收

- 冻结后先跑 19 例，再跑 100 例；修复后重新冻结并说明版本变化。
- 分别报告首轮/追问轮、每题型、对象保持、新维度完成、错码错行、错误拒答、无依据结论、数值正确性。
- 同时报告运行/裁判错误、p50/p95 延迟、模型调用和重试/降级次数。
- 至少三次重复评测，公开每次结果与波动，不只选择最佳一次。
- 错码归属、虚构维修/计算、越权使用 provisional 等安全错误单列，不能被平均分掩盖。
- 新旧成绩只有在同一 gold、模型和数据条件下才比较；必要时对存量答案重新评分，并标注无法复核项。
