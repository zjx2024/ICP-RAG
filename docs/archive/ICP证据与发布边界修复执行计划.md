## 目标与边界

修复审查中已复现的通用机制漏洞，不围绕 19 例答案增加固定问法或字段补写。保留七类文档、PostgreSQL 权威事实、确定性 FTA/RBD 算法、Dify、统一上传和图片证据。保留 Trae 的工程清理、现代历史召回、有界身份词召回与协议容错。模型、数据、排序权重不在本批调优；不自动提交、合并或恢复 100 例。

语义由模型判断；程序验证身份、适用范围、查询覆盖、来源与计算权限。查询未命中不是全库不存在，原记录可信不等于关联可信，字段值正确不等于回答对应。动态自然语言合同也是提示词，不能称为确定性证明。

## 重点反例（不限于现有合成身份）

- 当前码 A 与 MFL 明确码 B 冲突，即使名称和故障模式相同仍不能绑定；不同记录的模块和模式不能交叉拼成身份。
- 名称匹配仅提供候选，缺少显式跨表关系时不能宣称当前报码的确定维修程序。
- LLM 没选中候选、候选列表为空/截断、数据库失败、用户换对象，均不能变成全库未建模；旧终态 manifest 不授予本轮事实权限。
- API 不可直接上报但存在主动查询接口；用户换说法、字段相同但分问不同，不触发机械补写。
- 删除条件句后保留处置句、删除列表主体后保留标题，均须按最终文本重新审核或安全地声明本轮未完成，不能沿用剪前交付判定。
