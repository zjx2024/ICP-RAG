# 回答链路依赖与状态治理设计

2026-09-05，阶段 4 的实施输入与验证记录。回答拆分先在隔离副本验证，semantic-v3 的 19 例评测结束后才落地到工作区；落地后1398项后端回归通过。

## 依赖复核

四个 `answer_domain_*` 模块反向从 `answer.py` 导入 **48 个不同符号**。沿本模块函数引用递归展开，涉及 64 个函数及相关常量（105 个符号）；此外还依赖域模块中的私有函数。旧报告的 75 是重复导入计数，不能作为不同职责数量。

仅把这批符号搬到 `answer_helpers.py` 仍会循环：

- 证据窗口调用历史主目标/强度判断、故障候选匹配、架构角色和集合选择。
- 目标完整性调用目标域的 facet 映射、集合/角色解析和 RBD 正式结构投影。
- 历史与计算域还导入故障域的 `_prompt_payload_as_evidence`。

因此先分离纯数据规则与需要上下文/引用账本的服务，再移动编排；不通过延迟 import、动态 globals、重新导出互引来伪装解耦。

进一步把四个域模块的依赖也纳入展开，共涉及 143 个定义、4930 行原函数/常量。函数引用图不存在递归环，问题是模块职责交叉造成的 import 环。已按文本、字段目录、证据载荷、当前请求、领域纯规则、结构视图、集合、记录范围、窗口、上下文、事实单元、目标存在性和完整性拆为 15 个单向依赖模块；不是把全部符号堆到一个 helpers 文件。

隔离验证：143 个移动定义的 AST 与服务端原定义逐项一致；1391 项原有回归全部通过。新增三项护栏验证全体 answer 模块无环、下层不反向依赖编排、四个领域模块在独立进程中直接导入且不加载 answer 入口。旧私有导入路径暂时显式兼容导出，但下层不使用这些兼容路径。

## 拆分目标

| 职责 | 输入/输出及依赖边界 |
|---|---|
| 文本呈现原语 | Markdown、引用标记、明确格式的清理；不读 AgentState，不调用领域模块 |
| 证据载荷与字段目录 | 有界公开字段、身份格式、facet→权威字段/标签；单一来源，不含答案编排 |
| 领域纯规则 | 历史适用性/父案例、故障候选、架构集合、RBD 正式结构；显式传入数据，不反向读取回答窗口 |
| 证据选择 | 使用上层提供的当前对象/目标与上述规则，输出稳定有界候选；不生成答案 |
| 完整性与交付报告 | 输入最终答案、当前合同和已批准引用账本；输出缺失/交付记录，不决定新意图 |
| 模型编辑服务 | 负责有界调用、错误/超时/回显/无变化退出；使用显式上下文，不扩大用户任务 |
| answer 编排入口 | 选择模式、生成、编辑、校验、发布；依赖以上服务，禁止下层反向导入 |

验收应包括模块导入方向测试、从独立域入口直接导入、现有行为回归与真实 19 例比较。拆分本身不改排序权重或放宽权限；巨型函数按选择/验证/格式化职责分步拆，不以行数减少代替设计改进。

## 当前状态生命周期与约束

remaining-v11 新增约束：

- `query_frame.user_context_bindings` 由本轮目标模型选取，代码核验其 `message_id + quote` 来自当前有界历史中的用户消息；`user_input_query` 绑定当前问题，执行节点重新读取真实历史。它属于 `unverified_user_input`，不是工程事实、引用锚点或旧计算权限。无命中不抹掉输入；新报码及部分代码纠正优先，冲突的历史码不取第一/最后一个。
- 引用审核的 `source_attributions` 独立于事实字段绑定。模型识别声明所称的资料归属，代码核验原话和绑定资料 `doc_type`；缺少该审核字段或类型不一致不能批准事实。真实字段存在不代表任意资料都提供它；不以用户问句词表判断资料归属。
- `_answer_fields` 保留列表中的结构化对象，FTA 基本事件和历史步骤不再变成 Python 字典字符串；正式 FTA 显式门及其输入按组投影，初稿与引用都能看到可定位字段。不生成新关系、割集或概率。
- `model_runtime_policy` 将各角色输出上限同步到 `num_predict/max_tokens`，并给底层请求设置不超过节点预算的超时；重试使用剩余时间。同步线程不再保留原来的超长 socket 超时，但仍不宣称可强制取消远程推理。
- `ranking_policy` 只外置候选相关性权重，默认结果保持不变；合法配置必须是已知字段及有限的0～1数值。权限/身份标志与硬安全排序层不配置化，执行轨迹记录实际权重。

本批1514项后端回归、10项前端协议测试、npm ci及生产构建通过；真实remaining-v11小回归尚在执行。

| calculation_authorizations | 两个规划阶段的已验证共识 → calculator / gate | 仅当前原始问题授权；兼容 calculation_requests 不能独立授权 |

| 编辑器失败状态 | answer 当前调用内 → 后续编辑轮 | 每个请求重置，当前轮熔断；不得带到下一轮 |
| diagnostic_confidence | 旧链路兼容 | 新逻辑用 diagnostic_support，不称故障概率；先迁移消费者再删除 |

## 故障与观测边界

- 权威 PostgreSQL 失败与查询成功但无结果分开，不能伪装空结果。
- OpenSearch/HugeGraph 等可选补查故障允许降级，但要记录服务、原因、次数及本轮影响。
- tracing 故障不得拖垮主回答，也不能把采集失败当作“未发生重试”。
- 评测保存逐轮正文、引用、轨迹、模型/裁判及源指纹；只有完成的运行才能汇总为正式成绩。

前端另批治理关键 API/SSE 类型、统一上传和诊断状态交互；不新增产品入口，不因清理旧代码破坏 Dify 或工程图证据。

## 本批前端与评测归档

- 提取类型化 diagnosisStream：校验已知事件载荷，保留未知扩展事件兼容；支持多行 data、中文跨字节和 LF/CRLF，流提前结束不能当成 done。
- 页面不再直接把 JSON 作为 any；Evidence/Citation 合并为一份契约，候选目录的空公开引用编号明确为 null。
- 新增 10 项 Node 内置测试，不引入新测试框架依赖；CI 同时执行构建和这些协议测试。它们是关键协议/状态边界测试，不冒称完整浏览器交互测试。
- 评测文件输出逐例写入独立 checkpoint，保留稀疏原索引和未完成用例；未完成快照无总通过率，不能覆盖正式报告。归档失败明确非零退出。
- 补全编辑器共享预算已落地：全请求最多4次、每编辑器最多2次，相同编辑器/输入摘要不重复调用；超时与失败同样消耗预算。预算退出保留当前稿，mandatory安全/引用核验不受该可选预算影响。剩余重复调用实现仍可进一步收敛为统一服务。
- 初始化深拷贝历史，验证两状态的可变容器、嵌套锚点与交付清单不共享；恢复历史不会授予本轮计算权限或证据批准。回答局部的已审核会话/缺口单元不持久化为后续工程事实。
- tracing注册表统一生成聚合字段，增加模型选择、开放声明安全降级和补全预算退出；代码快照包含所有新回答层，静态测试防止拆分后漏计源指纹。
- 最新1430项后端回归、10项前端协议测试与生产构建通过。仍需真实19例无回退验收、更多开放语义后处理治理；浏览器技能运行组件缺失，统一上传/停止等真实交互不宣称通过。

后续共享来源视图批次已通过1456项后端回归：生成和引用验证使用相同字段坐标；RBD仍从原始图及当前合同复验，不能仅凭给模型看的摘要升级权限。公开压缩阶段保留本轮已审核的会话/查询边界，以及已经授权的公开字段视图，不重复以缺失私有状态为由清空它们。新增scope失败类型及公开可观测性，将模型未完成分类与需要用户补信息区别开。

## remaining-v13 最新补充

- `source_owned_field_view`位于共享证据层：只按当前来源-字段合同构造只读投影，原始证据不变；初稿、完整性和引用共用，避免不同阶段用不同字段填同一来源义务。
- `user_context_binding`从有界用户消息重新验证选择依据；`_hmc_lookup_query`在SQL调用边界消费经过校验的选择器，gate同步检查。选择历史用户输入不生成事实、不恢复计算权限；当前新码或部分纠正优先。
- `answer_request`共同提供有用户原文依据的工况，未提供时显式未知；不把规划器推测写成用户已确认阶段。
- 删除FTA结构末尾开放词/标题改写与按事件名称删行器，避免发布前绕过语义/引用审核重塑健康答案。
- v13的1526项后端回归及前端检查通过；v11实测1/5例、4/10轮及5轮裁判协议错误已归档。修复后完整效果仍待新报告验收。
