# ICP 问答链路预算与上限核查

2026-09-08。本文保留修复前的核查快照，并在下方区分本批已实施设置。范围为影响问答质量、发布和评测的主要上限，不是上传/解析/所有字符串清洗的全仓穷举。

## 本批实际生效规则

| 预算 | 当前规则与可观测性 |
|---|---|
| 输出 | Agent 配置优先，未设置才用注册模型默认。当前基线 Agent 4096、模型 8192 tokens；所有 ICP LLM 节点不再用 256/384/1200/2048 等常数覆盖。`max_tokens` 与 Ollama `num_predict` 同步。 |
| 输入 | 共享入口保留完整提示、历史和字段。Ollama 读取实际加载容量（未加载则读取模型信息），显式传递 `num_ctx`；当前观察值 262144 tokens。经版本兼容检查后用原生 `truncate=false/shift=false`，由服务端真实 tokenizer 拒绝容量溢出；字节数只记录传输规模，不做超限判断。输出预算不得占满上下文，生成阶段耗尽也拒发半截稿。 |
| 时间 | `ICP_AGENT_TOTAL_TIMEOUT_SECONDS` 默认 240 秒，整轮唯一截止时间，通过异步任务和线程上下文传递；节点及重试使用剩余时间。没有独立 420 秒 answer 总预算。传输 timeout 不得超过剩余时间，但取消不保证远程推理立即停止。 |
| 使用量 | LLM trace 增加提供方实际 token 用量、停止原因和有效预算；提供方未返回的用量保持缺失。`length` 等耗尽停止原因拒绝作为完整答案发布，并明确反馈输出预算问题。 |

已经退役：用户问题 12000 字符、API 历史 20 条、入口路由 8 条/单条 500 字、主规划/回答历史 16 条和 6000/18000 字符、入口澄清问题 300 字、入答 12/25 条及来源族配额、历史 Top-2/分数阈值、每记录 80 字段及 1200/3600 字符、模型候选 16 与组件 64、审核草稿/单行字符额度和来源句柄额度、自然语言分问 12 条限制。规划中的原话依据不再先截断再校验。发布引用表旧 25 条上限也已退役；能力说明与正文共享输出/完整历史/整轮时限；原话绑定与来源依据不再截到 1200/500 字。旧压缩接口因会删除原消息而停用，保留路径并返回 409，现有历史不受影响。上下文超量目前采用明确失败/提示分步，不宣称实现了任意大历史的自动压缩或智能分批。

评测删除了没有用户长度要求的 400/450/500 字符断言；正文、原问题和用于裁判的对话不再按字符截断。裁判选择程序编号的原始正文单元，由程序保存准确引文，仍逐维度核对含义、来源、否定条件及遗漏；裁判版本为 v13，36 个固定正反例校准通过。不能把去掉长度断言后的涨分当作内容涨分。

仍保留的边界：精确代码、身份、版本、来源与计算授权；检索首批 `top_k`、有界工具批次及锚点协议；图搜索/可靠性算法规模；纯 UI、日志、审计预览及旧 Dify 兼容链路的展示额度。这些不是正文长度额度，也不能用来证明已读完整资料。未本批穷举改动解析和上传限制。

验证：目前 1539 项后端测试、10 项前端测试、生产构建及编译/静态检查通过。第三次完整 19 例原始成绩为 10/19、29/40，包含容量误拦截、发布引用残留上限及裁判错误，不合格；相关问题修正后将独立再验收，详见本批实施记录。100 例继续暂停。

## 修复前生效链路（历史快照，以下数值不是新设置）

| 阶段 | 设置 | 性质与作用 |
|---|---|---|
| 用户问题 | 12000 字符 | API 输入硬上限，超出拒绝；`backend/agent/api/chat_router.py` |
| 19 例评测长度 | ARCH-02 数量追问 400；RBD-01 边界追问 500；RBD-02 边界追问 450 字符 | 测试硬断言，不截断产品答案；这三道问题原文均未要求这些字数 |
| 模型/Agent/正文预算 | 模型注册配置 8192 tokens；当前 Agent 4096；Ollama 正文节点再限为 1200 | 多层覆盖；`model_role_service.py`、`nodes/answer.py`；仅调模型管理页不解除正文上限 |
| 入口与规划输出 | 范围路由 256；本轮目标 2048；检索规划 2048 tokens | 输出预算；目标阶段可通过环境变量调整，有 512–8192 范围 |
| 补查与模型选择输出 | 补查提案 384；模型选择 1200 tokens | 仅限结构化提案，不是最终答案长度 |
| 只读审核输出 | 4096 tokens | 与作者分开；默认不启用长思考输出 |
| 历史读取与入模 | API 最近 20 条消息；规划/回答最多 16 条、单条 6000 字符、总计 18000 字符 | 共享 `answer_context_binding.py`；保留截断标志及历史引用命名空间，已不是旧版每条 600 字 |
| 会话锚点/目标 | 当前候选锚点最多 12；本轮自然语言分问最多 12 | 有界规划协议；历史锚点仍需本轮 PG 回读，不能继承旧结论权限 |
| 检索 | 当前 retrieval_top_k=12、sql_limit=12、kg_top_k=12；存储 locator 回读通常每类 8 条，硬上限 16 | 不是每种查询共用一个固定结果数；精确、完整集合、架构等有专门路径 |
| 入答证据窗口 | 常规 12 条，硬上限 25 | `nodes/answer_evidence_window.py`；全部获批证据不等于全部入模 |
| 单记录字段视图 | 最多 80 字段、单字段 1200 字符、合计 3600 字符、嵌套深度 5 | `citation_binding.py`；内容可能截断，会记录被截断路径 |
| 历史/模型聚焦 | 历史案例聚焦默认最多 2；工程模型候选最多 16，每候选组件视图最多 64 | 不代表库中只有这些记录；模型候选超量不会静默选取前 16 个授权 |
| 补查轮数 | 首轮结果后最多再决定一批，至多 5 个查询工具 | 不是开放式无限工具循环 |
| 审核输入格式 | 初稿最多 24000 字符；最多 80 个非空行单元；单单元最多 4000 字符 | 超限拒绝，不等于要求答案写这么长 |
| 审核来源选择 | 模型每单元最多提出 24 个句柄 | 程序补带同记录身份/调用参数不占这个模型提案额度，但只能来自当前有界来源集 |
| 审核重试 | 最多 3 次常规审核、最多 2 次作者修订；最终剪稿另需严格审核 | 同稿协议修复占原预算，不另加一条编辑链；全部受剩余总时限限制 |
| 图遍历 | 默认深度 2、40 节点、80 边、12 路径；硬上限 5、200、400、50；种子硬上限 20 | 防止图搜索无界扩张；当前适配器还将候选种子限制为 8 |
| RBD 计算 | 默认最大 12 条成功路径 | 容斥计算规模护栏；发现超量即禁止基于截断路径给出可靠度，不是允许漏路径计算 |
| 审计目录/工具展示 | 总证据目录 100；过程事件额外身份最多 75；单工具预览最多 8，摘要通常 260 字符 | 是展示/持久化预算，不能与权威原始记录上限混淆 |

字符按程序字符串长度计数，不等于中文字数，也不等于 tokens。当前 Ollama `/api/ps` 报告 Qwen3.8 27B 加载上下文为 262144 tokens；这不证明每次请求使用了全部容量，应用层上述视图预算往往先起作用。

## 修复前时间边界

| 层级 | 当前值 |
|---|---|
| 整轮 API 图执行 | 240 秒 |
| 入口范围 / 本轮目标 | 各 20 秒 |
| 检索规划 | 75 秒 |
| 工程模型选择 / 补查决策 | 各 30 秒 |
| 入答重排 | 25 秒 |
| 单次作者生成 | 120 秒 |
| 单次审核 | 180 秒 |
| answer 节点合计 | 420 秒 |
| 评测 HTTP/SSE 操作 / 裁判请求 | 300 / 60 秒 |

**存在预算不一致：answer 的 420 秒不是线上请求可实际完整使用的预算，外层 240 秒会先取消。** 模型注册的 timeout=3000 也会被阶段传输预算收窄。上层超时不保证远程模型立刻停止计算，不能把取消请求等同于算力已释放。

## 原简化方案（本批实施依据）

原则：**能从用户要求、真实模型容量或算法成本推出的才是有效边界；其余不另拍常数。** 不建设新的多阶段预算决策智能体，也不为每类问题制定字数档位。以下保留当时方案；实际实现和边界以文首为准。

### 一、资源预算只维护一处

| 项目 | 新规则 | 本次不做的事 |
|---|---|---|
| 输出 | 保留已有的“Agent 配置优先、未设置才用模型默认”规则，由一个入口解析有效输出预算；删除节点 1200/2048/256/384 等隐藏覆写。当前 Agent 的 4096 作为配置基线，不再重新发明一个值。短 JSON 由 schema 和任务自然结束，不要求填满预算。 | 不把所有阶段都改成一个更大的拍脑袋常数；不改变模型或思考配置来混入另一变量 |
| 输入上下文 | 以实际使用模型的可用上下文，扣除本次输出预算及必须保留的提示内容为边界。当前问题和纠正必须保留；证据与历史按任务相关性占用剩余空间。计量不足时记录估算方式和实际用量，不宣称精确计数。 | 不因模型宣称有 262144 tokens 就每次塞满；不同时保留“16 条/6000 字/18000 字”和“25 条/80 字段/3600 字”多套互不协调的静默截断 |
| 时间 | 整轮只有一个截止时间，节点与重试使用剩余时间；删除独立 420 秒总预算和各节点互相不一致的业务超时。当前有效 240 秒先作为基线沿用，是否调整由完整运行耗时与用户可接受等待时间决定。连接失败检测仍可有传输层超时。 | 不直接猜一个 360/600/900 秒；不靠提高时间上限掩盖重复生成；不声称取消即停止了远程计算 |

统一入口输出“本次有效值、使用量、截断/耗尽原因”即可，不增加多套配置和额外 LLM 调度器。模型总容量是物理边界，Agent 输出设置是业务配置，不再混称同一个 max_tokens。当前追踪主要只有 response_chars；实施时透传提供方实际 token 用量和停止原因，不用字符数冒充 token 计量，也不能只凭答案末尾不完整就断言触发了输出上限。

### 二、取消没有依据的内容上限

- 删除 19 例中 400/500/450 的硬长度断言，统一记录长度用于观察。是否啰嗦看重复、偏题和遗漏，不替换成另一组字数。只有用户问题明确要求字数或条目数时，才按该要求验收。
- 审核以实际初稿单元和实际提供的来源集合校验完整性、身份与支持关系，不再因额外的“最多 80 单元/24 来源”等固定内容额度否决一个原本合法的回答。输出和请求资源仍受统一预算保护，异常结构仍须拒绝。
- top_k 只作为首批召回的性能参数，不作为资料全集、唯一对象或最终可答范围。取消以固定“2 个历史案例、16 个模型候选”强行确定所指对象的做法；先保留候选和精确身份差异，确有歧义时说明歧义。
- 去除各阶段重复砍同一批证据的操作。完整集合走 PG 的完整集合/分页路径；超出可用上下文时明确报告覆盖范围或请求分步，不将截断伪装成“没有”“只有这些”。不承诺一次读完任意规模的库。

### 三、安全与算法护栏单独保留

- 精确报码、记录和构型一致性、PG 权威来源、已验证图状态、用户计算授权、禁止无证据唯一诊断不属于“可放宽的篇幅限制”，保持不变。
- 图遍历和 RBD 计算仍有规模保护；暂保留已验证的保护值。后续若需调整，依据图规模、算法复杂度、实测执行成本及剩余预算，不另猜更大数字。超过能力时返回受限状态，不输出截断后的假数值。
- 保留有界修复和取消能力，不新增补写编辑器，不用“直到通过”为循环终止条件。本批先不同时调整重试次数，避免把多种行为变化混在一起。

## 最小实施顺序与验收

1. **完成当前冻结测试（已完成执行）**：19 例/40 轮全部发送，原始成绩 12/19、29/40；运行错误 0，裁判协议错误 3，评分完整性未通过。保存正文、实际来源、自动失败、裁判失败、长度/耗时；它是调整前基线，不改写原报告。其中一轮语义通过，仅因 503 字符超过 500 字符失败，直接说明该长度断言不代表回答质量。当前历史记录“已回读且获批却未使用”的例子须纳入证据选择回归，不能只调 top_k。详见 [职责交接完善验收记录](ICP职责交接完善验收记录.md)。
2. **一次职责收敛**：统一输出/上下文/截止时间入口，删除对应散落常数及重复裁剪；同时统一删除无用户依据的长度断言。代码变更需有旧路径退役清单，不能只套一个新 Budget 类而旧限制照常执行。
3. **同题验证，不拼分**：正常简答、复杂多问、长历史、完整集合、明确字数要求、错误来源、超时取消、超限计算均覆盖。19 例重新冻结单独跑；新旧长度口径分列，不把删断言产生的涨分当成内容提升。100 例继续暂停。

验收看：相关证据是否真正进入回答、分问是否完成、错误事实是否被拒绝，以及截断/耗尽是否可解释；不以“上限更大”或“平均字数更多”判定成功。
