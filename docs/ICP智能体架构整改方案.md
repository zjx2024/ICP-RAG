### 一句话目标

让系统把主要精力用于“找对资料、回答本轮问题”，而不是“为每段答案填写完整的证明表”。严格阻止事实和安全错误，但不把非必要补充、审核格式困难和事实错误混成一种失败。

### 1. 为什么修改，以及暂不修改什么

已有证据说明三种问题并存：

- 真实回答问题：错行、相似报码混用、忽略关键适用条件、无根据扩展因果或运行许可。
- 审核机制问题：Markdown 身份误判；来源选取协议出错导致改写正确正文；长审核 JSON 耗尽输出预算；自然的多模型比较被逐行数值校验拒绝。部分误判已修复，不能当成当前仍全部存在。
- 评测口径问题：用户只要求使用已验证参数，却被规划目标要求列出全部参数；用户问核查方法，评测无条件要求逐行介绍 API 上报能力。后者应先核对必要性，不能直接据失败给产品加规则。

最近的 `failfast19-20260908.WEMakP/attempt-7.json` 执行 6 例/13 轮，5 例/12 轮通过，SOURCE-01 追问失败后停止；它不是完整 19 例成绩。该追问内部审核通过，外部 `expected_dimension` 因遗漏 API 能力区分失败。详见 [定向诊断与原始运行账本](ICP追问审核失败定向诊断.md)。

本批冻结检索、模型、数据、计算算法和现有运行预算，优先隔离回答组织、审核和评测问题。不重写解析器、数据库、图服务或前端，不新增第八类知识文档，不改变统一上传、Dify 和工程图证据能力。若对照证明错误发生在上游，则单独定位，不拿审核补丁代替检索修复。

### 2. 先区分“不能说错”与“还可以说得更好”

| 类别 | 判断依据 | 在线处理 | 评测处理 |
|---|---|---|---|
| 事实/安全错误 | 错码错行、无证据维修/运行许可、伪造接口、越权计算、结果错配等 | 修订；仍不能核验则不发布相关工程断言，不用免责声明豁免 | 必须失败，独立报告 |
| 核心任务未完成 | 用户明确分问未答、追问重放首轮、违反实质条件 | 反馈一次修订；来源确实不足则说明边界，不能把漏答包装成缺资料 | 核心完成失败；与事实错误分列 |
| 非必要完善 | 可选背景、额外字段、非必要重复、表达偏好 | 不因这一项重写或拒发 | 记录建议，不让整例失败 |
| 审核/运行故障 | 无效协议、超时、缺失引用坐标、审核未完成 | 明确系统未完成核验；不发布未经核验的初稿 | 系统故障，不冒充知识能力错误或通过 |

这里的语义分类由模型结合原问题、历史与来源判断，并用人工校准样例验收；不是按固定中文词汇、用例 ID 或正则判断问答对应度。代码继续承担身份、版本、引用存在性、计算授权和确定性数值等可机械验证的职责。

“必要条件”的统一判据：省略后是否会改变用户对对象、因果、可执行性或结果适用性的理解。用户明确追问该条件时必须回答；没有询问的条件若会使已给建议失实或不可执行，也必须说明。其余资料字段不自动变为必答项。

MFL 争议样例按此原则处理：明确把不可直接上报写成可直接调用，必须失败；只转述原文的人工/物理核查方法，不因没罗列全部 API 字段自动失败；若把未确认的接口操作写成已经可执行，须补充限制。`api_reportable=false` 不等于没有人工检查方法。SOURCE-01 的原稿按完整上下文复核，保留裁决理由；本方案不预先将它改为通过。

### 3. 目标流程：保留一处审核，减掉逐段证明协议

```text
原问题与必要历史
→ 既有检索、权威回读、按需图与计算
→ 带身份及适用条件的证据包
→ 一次问题驱动生成，直接标出记录来源
→ 引用/权限/数值检查 + 一次整篇语义审核
→ 无实质问题即发布；有问题最多一次针对性修订并复核
→ 纯引用与格式渲染，不再补写或剪裁事实
```

**这与当前实现的实质区别不是再增加一个审核节点，而是替换审核的工作内容与输出合同：**

1. **作者负责正文与引用。** 根据当前问题选取证据，使用请求内稳定记录 ID 标注来源；不重述全部字段，不让规划提示增加任务。查询结果存在限制时保留限制，不能把检索排名当成根因或跨表关联。
2. **代码负责引用身份与工程硬约束。** 普通知识事实按有版本的记录/证据片段追溯；计算结果继续绑定具体计算凭据、模型、输入参数、结果字段和单位。原始字段坐标留在日志及证据包，不要求审核者为每个普通段落重复枚举。
3. **审核者负责阅读完整答案并指出实质问题。** 输入仍有完整正文、原问题、必要历史和同批获批证据；只输出明确结论及有问题的原文位置、问题类别、依据。通过的段落不逐项输出来源列表、断言标签和文档类型。缺答反馈须对应用户原始分问或实质条件，不能照抄参考答案或规划附加目标。
4. **质量建议不触发改稿。** 审核结论区分可发布、需要修订、无法完成审核；不能把“无依据判错”或“协议未完成”解释为可发布。问题清单为空也必须有完整、有效的审核结论。
5. **有实质问题最多修订一次，再审核最终文本。** 目标正常为作者一次、审核一次；需修订时再各一次。该次数是限制反复改稿导致漂移的结构设计，不是新增字符上限；须用 M3 的时延与质量对照验证。不能因次数用尽而放行未核验稿，也不继续自动剪裁、剪后重审和多层兜底。

代码生成并保存草稿哈希、证据版本和引用映射，保证审核的是将要发布的那一版。审核模型仍可能误判；“已审核”不是数学证明，必须独立测量其误拒绝与漏检。

#### 普通引用与数值引用如何兼顾

- 普通引用：模型选择记录，程序检查记录身份、当前授权及已知构型/版本；整篇语义审核判断该记录是否真的支持所述事实。同名或引用确实存在都不自动证明语义支持。
- 数值引用：保留确定性算法及精确结果校验，把检查对象从“整个物理行只能绑定一个模型”改为“每个结果陈述绑定自己的计算凭据”。明确引用的同段多模型比较应允许；数值互换、借用邻居参数、任务时间/单位错配仍拒绝。
- 数值绑定的替代实现必须先通过正确比较与数值互换的成对测试。没有可靠绑定时继续拒绝该数值断言，不能先删检查、把多记录数值合并成一个允许值集合，也不要求所有答案固定换行来迁就程序。
- 事实与限制同包：MFL 方法与上报能力、FMECA 影响与任务阶段、历史处置与发生/恢复条件一起可见。不是强制逐项输出；跨记录不能借用条件，也不把方法或条件缺项补造出来。

#### 哪些旧职责必须同期退役

- 默认链路中的全量逐单元 v4 证明表，以及仅为其完整性服务的来源重选/分类补齐循环。
- 由审核模型重新选择全部最终引用的第二套所有权；最终引用以作者选择并通过核验的映射为准，修订引用必须对修订后正文再核验。
- “一行多模型数值即失败”的排版约束：只在上述精确绑定替代验证通过后移除。
- 因非必要完整性建议触发改稿，以及删除段落后再审核的自动挽救循环。最终正文的事实删改由作者在唯一修订中负责，渲染器不裁剪。

现有精确身份、PG 权威回读、provisional 限制、图关系再授权、历史命名空间、私有诊断记录及安全测试继续保留。旧 v3/v4 快照的读取兼容仅留在离线回放路径，不再作为默认线上双实现长期维护。不为凑删除行数删除安全能力。

### 4. 分五个阶段实施，每阶段有明确结束条件

| 阶段 | 要做什么 | 交付与进入下一阶段的条件 |
|---|---|---|
| M0 校准判分 | 对全部 19 例/40 轮的要求逐项区分必要内容、禁止错误、可选完善；核对现有失败与正常样本 | 每项必答要求能指回用户分问或说明省略造成的实质误导；形成带依据的校准集与争议清单。校准前不因 SOURCE-01 再加产品规则 |
| M1 明确引用职责 | 冻结相同证据输入；作者持有稳定引用；普通事实按记录核验，数值绑定计算凭据；让字段与限制保持上下文 | 随机记录 ID、不同构型、相似码、数字互换、合法同段比较均有成对测试；无新模型/检索调参 |
| M2 替换重审核 | 用整篇审核、问题清单和一次修订替换逐段证明与剪裁循环；精简重复提示；同期删除旧入口/状态 | 默认调用路径只有一套；旧协议只可离线回放；协议损坏、未审核、实质错误仍不能发布；前后端协议兼容 |

| M4 真实多轮验收 | 使用冻结后的标准运行完整 19 例；通过后审计 100 例并逐步扩展 | 首败即停、失败优先排序；保留所有独立报告。完整 19 例须同版独立通过，不能拼旧分数；100 例覆盖与来源审计合格后才作为后续任务启动 |

M0 校准先以现有原问题和原始资料为依据，不改用户问题来迎合现有答案，不删除已发现的真正错误断言。修订 rubric 单独版本化；若需重评旧结果，生成单独报告，禁止覆盖原成绩。校准样例至少包含：正确但简短的答案、完整但错行的答案、真实漏答、正当澄清、限制遗漏造成实质错误、只是漏掉可选细节、合法比较、数值互换、格式变化及协议错误。样例从已捕获正常/失败文本与成对变体构成，不只选本次失败题。

M3 是离线实验，不恢复被用户否定的线上单例闯关流程。先零模型重放可机械确认的问题，再做事先列定的混合样本配对语义审核，不因结果不理想无限重复到通过。顺序轮换，输入与预算一致；同草稿审核实验和端到端生成实验分开报告。修改前锁定样例与判分依据，保留未参与修改的对照题。条件允许时盲化新旧答案次序，由人工核对争议与高风险样本，不把同一模型自审当作独立真值。

M4 继续用户指定流程：完整 19 例，按历史最新结果排序为“失败 → 未测 → 已通过”，例内多轮顺序不变，所有通过项末尾重测。事实错误、核心任务失败、系统故障均首败即停；可选完善按 M0 已冻结分类记录为建议，不在运行中临时改为不影响成绩。判分存在新争议也暂停复核，不自动视为通过。

100 例审计保留所有样例身份，核对多轮指代、模糊与具体问题、相关深入追问、无关话题/范围外、换对象与纠正、无资料/缺条件、精确代码、不同版本及图计算边界；检查参考来源与断言是否相符、是否无依据强制工具路径或附加字段。若不足，先补缺失覆盖，不能仅因“有 100 例”就开跑；已经参与调参的样例不得称为盲测。

### 5. 如何判断“确实变好”，而不是只让分数好看

分开报告以下结果，不用一个通过率掩盖彼此：

1. **事实与安全**：哪些错误答案被放过，哪些正确答案被误拒；分别给出分母和原文证据。
2. **核心任务完成**：是否保持当前对象，真正回答本轮分问及必要条件；追问不是重放旧列表。
3. **系统可用性**：是否交付有用答案或合理澄清；拒发、审核故障、超时单列，不能用免责声明充数。
4. **资源开销**：每轮调用数、实际输入/输出 token、总耗时及有足够样本时的分位数；与同条件旧链路配对。
5. **可选完善**：冗余、排版、扩展信息等独立记录，不与错码错数值等价。

阶段结束不靠单测数量或主观观感。M3 的固定硬安全负例必须全部仍拒绝，正确配对样本必须支持预期表达；这是已知回归要求，不宣称未知场景零风险。若仅少拒发但新增错码、错数值或无证据工程断言，不能切换；若仍无净收益，停止扩大实施并报告证据，不通过继续加循环、加提示或加预算掩盖原因。模型/数据替换若有必要，另开独立变量实验，不能与本批收益混算。

## 1. 目标和不变边界

目标：用户只需自然描述现象并连续追问，系统能保持对象、回应新问题、组织可复核证据；不能以字段出现、工具运行或单元测试通过自证回答质量。

| 边界 | 单一写入者与职责 | 禁止事项 |
|---|---|---|
| TaskContext | 任务理解；原问题、自然语言子问题、当前对象/用户纠正、显式来源约束 | 用有限字段目录替代开放问题；后续节点偷偷改写用户目标 |
| CaseContext | 会话更新；用户观察、候选/反证、未决事项、历史交付的来源与轮次 | 把旧回答当真源；因字段讲过而禁止解释、比较或纠错 |
| EvidencePacket | 证据组织；权威身份、字段、来源、适用性、关联状态与查询覆盖 | 名称相同即合并；投影视图没显示即断言原文没有 |
| DomainResult | 现有领域工具；确定性查询/图再授权/计算 | LLM 自造代码、图关系、参数或可靠度 |
| AnswerDraft | 一个回答责任方；围绕本轮问题综合，区分事实/推断/未知 | 字段枚举代替因果、顺序、核对或条件 |
| PublicationReview | 统一审核；机械身份与数值检查 + 语义对应度检查 | 多个编辑器无条件轮流改写；仅引文字面存在即视为支持命题 |
| PublicAnswer | 纯渲染；引用编号、格式、兼容 SSE | 再次用关键词删改正文或补充诊断 |

这些是职责边界，不要求一次新建七个抽象框架。优先纯函数、小型类型和既有工具适配；用实验决定迁移范围。

## 4. 阶段 A：四种实验条件

1. **current**：完整现有流程，记录真实初稿及中间变化。不得把重放成功当作原运行错误已复现。
2. **retrieved_minimal**：同一次调用的证据和历史，使用简洁问题驱动提示，一次生成，不调用当前答案编辑链。仅供离线比较，不进入生产 API。
3. **reference_minimal**：单独的离线来源参考条件，从冻结源坐标读取摘录。明确标记使用评测来源，不计作端到端成绩；摘录可能不完整，不能直接称为理论上限；不把 rubric 或标准答案送给生成器。
4. **simplified**：B/C/D 实现后用独立入口比较精简链路，同一历史和运行配置；证明有效后才切换默认。

控制变量：固定问题、历史、来源、模型配置、评测器和代码指纹；每种条件保留全文、引用、错误、延迟；随机/轮换条件顺序，重复而不择优；逐轮重放与闭环多轮评测分别报告。参考来源不能流入 current/retrieved_minimal。

观测默认关闭，仅在显式本地诊断上下文中收集。不得落盘凭据、模型连接密钥或隐式推理；不得经 SSE/公开 trace 暴露内部稿。本地产物使用独立目录、限制权限且拒绝覆盖。异常必须可见，不能产出假成功。

衡量：对象保持、当前分问完成、事实支持/来源归属、必要条件/比较/顺序、错误拒答、错码错行、数值/授权、安全错误；另记录证据身份集合、阶段文本变化、调用和延迟。字面 diff 只定位改动，不能自动判为质量损失。

先用覆盖不同任务的诊断子集验证实验装置，再扩大到冻结 19 例。不能只选失败题，也不能按测试 ID 对生产分支施加行为。

## 5. B/C/D 的实施细节

### B：证据是带身份和适用范围的记录，不是相似片段堆叠

- 记录身份至少包括 doc_type、doc_id、业务 ID，以及存在的构型/修订；字段证据保持 claim 级身份。未知身份不按标题合并。
- 召回用于发现候选；回 PG 重读证明记录真实性；对当前问题的相关性和足够性另外判断。
- 同对象跨源关联只接受显式字段/代码；语义相近记录单列，不冒充同报码或同案例。
- 查询覆盖区分未执行、成功有结果、成功空、范围不完整、服务错误；字段区分完整读取、裁剪/截断、明确空值。任何局部缺失都不能升级为全库不存在。
- 完整清单以权威集合/计数为准；历史案例保留条件、观察、检查、处置、结果的原有上下文；计算继续复用原算法和门禁。

### C：减少语义状态的重复所有权

- 首先沿用可验证锚点和用户消息身份，增加自然语言本轮目标；现有字段合同暂作检索提示与兼容输出。
- 工具权限按数据域、安全和资源约束，检索选择按任务；显式来源限制仍严格执行，计算权限不随检索扩大。
- 对话摘要保存已知与未决，携带来源轮次；不逐层复制另一份“意图真相”。后续模块只能报告缺口或请求补查，不能自行改题。
- 当前用户更正优先；对比上轮需读取实际交付文本，而不是根据字段 manifest 推定。

### D：一个正文责任方，渲染不再做语义裁判

- 用本轮问题、CaseContext、EvidencePacket 生成答案，避免长篇重复领域义务提示。
- 审核反馈指向具体句子、证据身份和未答分问；最多一次针对性修订作为初始实验预算，是否调整须有测量依据。
- 身份/来源/数值硬校验不交给 LLM；语义判断不交给固定词表。安全失败明确报告，不能默默删至答非所问后声称完整。
- 内部引用使用稳定 evidence_id，编号仅渲染时生成。若仍使用旧编号适配，必须保持双射且不丢失审核绑定。
- 完成度在最终文本上审核；自动观测明确未验证时，不自报全部完成。

## 7. 切换与验收标准

- **安全硬门槛**：验收样例不得出现跨报码归属、虚构维修/数值、未授权计算、provisional 正式结论；出现即不切换。
- **因果比较门槛**：配对条件的语义提升须在重复运行中保持，报告改善与退步题，不只看平均分；裁判错误不计普通错答。样本量不足时不声称统计显著。
- **全量发布目标**：19/40 与 100/216 分别报告；三次均达到 ≥90% 可评轮次语义合格、≥80% 完整会话合格；运行错误与裁判错误目标为 0，非零须修复/复测而非降低分母粉饰。目标在此预先登记，不因结果不好改低。
- 延迟与模型调用不劣于同条件冻结基线；若质量改善需增加成本，单列收益/代价后决定，不隐藏。
- 对关键安全/边界答案需领域人员复核；编码智能体复核不冒充专家签审。未获真实资料前只交付合成回归验收。
- 迁移阶段使用内部实验入口和冻结快照，不添加用户产品开关；切换验收与旧职责删除属于同一批，保留报告和必要兼容接口，不在运行时长期叠加两套实现。
