## 1. 目标和不变边界

目标：用户只需自然描述现象并连续追问，系统能保持对象、回应新问题、组织可复核证据；不能以字段出现、工具运行或单元测试通过自证回答质量。

- 七类文档、统一上传、Dify 原路径、工程图与原文访问均保留。
- PostgreSQL 是权威事实；OpenSearch 和 HugeGraph 是可重建投影。
- 精确代码、业务身份、构型/版本、引用、计算参数由代码校验；不以自然语言固定词判断问题或答案是否合格。
- 视觉 provisional 不支持正式拓扑/数值；计算须当前用户授权；不捏造维修程序或跨文档关联。
- 历史模型回答仅证明“先前说过什么”，不能成为当前工程事实。纠正和话题返回必须可表达。
- 不擅自更换模型服务，不自动提交/推送/合并，不覆盖用户已有修改。不同实验结果不得混算。2026-09-06 用户另行授权升级 Ollama、部署 Qwen3.8 27B 并默认使用：下载可与整改并行，模型完整验证前保留原默认配置；切换作为独立变更记账，评测重新冻结。

## 2. 目标职责与数据流

```text
当前原问题 + 会话进展
→ 统一任务理解
→ 查询/补查（精确记录、完整集合、语义候选、已授权图/计算）
→ 当前对象证据包
→ 问题驱动的答案
→ 一处发布校验 + 有界修订
→ 纯格式/引用渲染
→ 记录本轮实际交付和未决问题
```

| 边界 | 单一写入者与职责 | 禁止事项 |
|---|---|---|
| TaskContext | 任务理解；原问题、自然语言子问题、当前对象/用户纠正、显式来源约束 | 用有限字段目录替代开放问题；后续节点偷偷改写用户目标 |
| CaseContext | 会话更新；用户观察、候选/反证、未决事项、历史交付的来源与轮次 | 把旧回答当真源；因字段讲过而禁止解释、比较或纠错 |
| EvidencePacket | 证据组织；权威身份、字段、来源、适用性、关联状态与查询覆盖 | 名称相同即合并；投影视图没显示即断言原文没有 |
| DomainResult | 现有领域工具；确定性查询/图再授权/计算 | LLM 自造代码、图关系、参数或可靠度 |
| AnswerDraft | 一个回答责任方；围绕本轮问题综合，区分事实/推断/未知 | 字段枚举代替因果、顺序、核对或条件 |
| PublicationReview | 统一审核；机械身份与数值检查 + 语义对应度检查 | 多个编辑器无条件轮流改写；仅引文字面存在即视为支持命题 |
| PublicAnswer | 纯渲染；引用编号、格式、兼容 SSE | 再次用关键词删改正文或补充诊断 |

这些是职责边界，不要求一次新建七个抽象框架。优先纯函数、小型类型和既有工具适配；用实验决定迁移范围。

3. 分别报告运行代码、测试、工具脚本的增删；代码行数不是唯一门槛，但运行代码净增必须解释新增必要能力及消除的旧职责。不得以测试数量充当质量改善。
4. 比较发布前后正文、实际模型调用、同题语义结果和安全回归。不能靠去掉校验减少调用，也不能只说“零运行错误”。
5. 实验需要旧实现时使用冻结快照/离线回放，不在默认链路长期保留双实现或产品开关。确认替换后同批删除旧职责，不延期至 E。

## 4. 阶段 A：四种实验条件

1. **current**：完整现有流程，记录真实初稿及中间变化。不得把重放成功当作原运行错误已复现。
2. **retrieved_minimal**：同一次调用的证据和历史，使用简洁问题驱动提示，一次生成，不调用当前答案编辑链。仅供离线比较，不进入生产 API。
3. **reference_minimal**：单独的离线来源参考条件，从冻结源坐标读取摘录。明确标记使用评测来源，不计作端到端成绩；摘录可能不完整，不能直接称为理论上限；不把 rubric 或标准答案送给生成器。
4. **simplified**：B/C/D 实现后用独立入口比较精简链路，同一历史和运行配置；证明有效后才切换默认。

控制变量：固定问题、历史、来源、模型配置、评测器和代码指纹；每种条件保留全文、引用、错误、延迟；随机/轮换条件顺序，重复而不择优；逐轮重放与闭环多轮评测分别报告。参考来源不能流入 current/retrieved_minimal。

观测默认关闭，仅在显式本地诊断上下文中收集。不得落盘凭据、模型连接密钥或隐式推理；不得经 SSE/公开 trace 暴露内部稿。本地产物使用独立目录、限制权限且拒绝覆盖。异常必须可见，不能产出假成功。

衡量：对象保持、当前分问完成、事实支持/来源归属、必要条件/比较/顺序、错误拒答、错码错行、数值/授权、安全错误；另记录证据身份集合、阶段文本变化、调用和延迟。字面 diff 只定位改动，不能自动判为质量损失。

先用覆盖不同任务的诊断子集验证实验装置，再扩大到冻结 19 例。不能只选失败题，也不能按测试 ID 对生产分支施加行为。

## 5. B/C/D 的实施细节

### B：证据是带身份和适用范围的记录，不是相似片段堆叠

- 记录身份至少包括 doc_type、doc_id、业务 ID，以及存在的构型/修订；字段证据保持 claim 级身份。未知身份不按标题合并。
- 召回用于发现候选；回 PG 重读证明记录真实性；对当前问题的相关性和足够性另外判断。
- 同对象跨源关联只接受显式字段/代码；语义相近记录单列，不冒充同报码或同案例。
- 查询覆盖区分未执行、成功有结果、成功空、范围不完整、服务错误；字段区分完整读取、裁剪/截断、明确空值。任何局部缺失都不能升级为全库不存在。
- 完整清单以权威集合/计数为准；历史案例保留条件、观察、检查、处置、结果的原有上下文；计算继续复用原算法和门禁。

### C：减少语义状态的重复所有权

- 首先沿用可验证锚点和用户消息身份，增加自然语言本轮目标；现有字段合同暂作检索提示与兼容输出。
- 工具权限按数据域、安全和资源约束，检索选择按任务；显式来源限制仍严格执行，计算权限不随检索扩大。
- 对话摘要保存已知与未决，携带来源轮次；不逐层复制另一份“意图真相”。后续模块只能报告缺口或请求补查，不能自行改题。
- 当前用户更正优先；对比上轮需读取实际交付文本，而不是根据字段 manifest 推定。

### D：一个正文责任方，渲染不再做语义裁判

- 用本轮问题、CaseContext、EvidencePacket 生成答案，避免长篇重复领域义务提示。
- 审核反馈指向具体句子、证据身份和未答分问；最多一次针对性修订作为初始实验预算，是否调整须有测量依据。
- 身份/来源/数值硬校验不交给 LLM；语义判断不交给固定词表。安全失败明确报告，不能默默删至答非所问后声称完整。
- 内部引用使用稳定 evidence_id，编号仅渲染时生成。若仍使用旧编号适配，必须保持双射且不丢失审核绑定。
- 完成度在最终文本上审核；自动观测明确未验证时，不自报全部完成。

## 7. 切换与验收标准

- **安全硬门槛**：验收样例不得出现跨报码归属、虚构维修/数值、未授权计算、provisional 正式结论；出现即不切换。
- **因果比较门槛**：配对条件的语义提升须在重复运行中保持，报告改善与退步题，不只看平均分；裁判错误不计普通错答。样本量不足时不声称统计显著。
- **全量发布目标**：19/40 与 100/216 分别报告；三次均达到 ≥90% 可评轮次语义合格、≥80% 完整会话合格；运行错误与裁判错误目标为 0，非零须修复/复测而非降低分母粉饰。目标在此预先登记，不因结果不好改低。
- 延迟与模型调用不劣于同条件冻结基线；若质量改善需增加成本，单列收益/代价后决定，不隐藏。
- 对关键安全/边界答案需领域人员复核；编码智能体复核不冒充专家签审。未获真实资料前只交付合成回归验收。
- 迁移阶段使用内部实验入口和冻结快照，不添加用户产品开关；切换验收与旧职责删除属于同一批，保留报告和必要兼容接口，不在运行时长期叠加两套实现。
