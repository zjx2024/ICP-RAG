## 状态与范围

代码职责替换已实施，工程检查通过，小样本恢复了完整审核发布。**不等于整体语义验收通过，也不是新的 19/100 例成绩。** 不能因本轮结果降低原验收门槛。

本批未修改模型注册、默认角色、数据库、检索、规划、七类入口、统一上传、Dify 或工程图产品边界。仍使用 Qwen3.8 27B；生成参数及 1200 token 上限不变。审核协议预算从 8192 降为 4096 token，因为不再复制正文和字段引文。

## 职责替换

| 责任 | 原 v1 | 当前 v2 |
|---|---|---|
| 正文 | 审核模型再编写最终正文 | 只有回答模型写正文，审核只读 |
| 来源 | 模型复制编号、路径、引文及多类绑定数组 | 程序提供字段句柄和来源身份，模型选择 |
| 目标 | 审核另写目标及正反向关联 | 原问题与规划的自然目标由程序编号，逐项核查 |
| 反馈 | 验证失败直接终止 | 一次反馈驱动修订，再完整审核 |
| 绑定错误 | 修订责任不清 | 具体错误同时返回回答者与下一次审核者 |
| 发布 | 纯引用渲染 | 保留；审核通过前不发布任何正文 |

正常路径 2 次模型调用，需要修订时最多 4 次。回答链共享 420 秒总期限，保留单次生成 120 秒、审核 180 秒及传输超时。超时、取消、第二次审核失败不回填初稿，不删成残片冒充完整回答。

保留的边界：

- 工程事实须选择本轮批准记录；会话只证明此前说过什么，交付进度不成为事实依据。
- 完整业务身份、前导零、通配符、API、记录归属和所声明的文档类型仍机械验证。
- 正式拓扑、唯一诊断、确定性计算、数值等值及原话授权不放宽；provisional/quarantined 不支持正式结论。
- 查询状态或方法边界可以完整回答负面问题，不强求肯定工程事实。
- 标题、脚注、免责声明也须语义审核；纯行文衔接无需虚构来源，但不能绕过具体身份校验。
- 最终引用由核验后的字段选择决定，初稿编号只是线索。未知编号仍拒绝，不用相似记录填补。
- 脚注完整定位须等于当前记录的来源或文档名，不可编造表号/行号；有效标签保留。

本批没有按测试 ID、特定故障值或自然语言固定词决定回答是否通过。封闭协议、引用语法及业务代码语法不是问法词表。语义判断仍可能出错，必须独立验收。

## 同批退役与工程变化

删除 v1 正文重写/重复引文/反向目标关联协议，不留双链开关。同时删除旧会话与观察引文验证器、字面摘录与来源归属旧协议验证器，以及未使用的来源词语正则表。

公开 trace 只增加审核轮次、结果、错误码和段落编号，不包含内部稿、字段值或完整反馈。私有快照补齐系统提示、检索改写、精确绑定等实际入答状态；旧快照不足时不得构造权威绑定。

增加诊断子命令 replay-answer：固定原初稿、历史、上下文、引用和生成模型，只检验审核/修订；不重检索、不创建会话、不读取 gold、不冒充闭环。

相对本批前 source-before-review-v2.tar.gz：后端 +350/-479（净减 129）；测试 +436/-821；诊断脚本 +105/-1。测试行数减少源于旧协议迁移和重复场景合并，不用数量证明质量。

## 实验记录

目录均在 .artifacts/evals/architecture-20260906/，原始结果不覆盖。

| 产物 | 结果与口径 |
|---|---|
| replay-review-v2-mixed-1 | 调用模型前发现旧快照漏存系统提示，中止。只允许从已保存完整提示逐字恢复该槽位 |
| replay-review-v2-mixed-2 | HMC 被格式限制拦截；RBD 旧快照缺少绑定、窗口不能重建，中止。不得放宽配对检查 |
| replay-review-v2-valid-1 / valid-2 | 各跑两个正常样本、重复两次；历史发布、HMC 拒发。暴露重复编号合同、纯行文类型性失败、审核者未收到自身校验反馈等问题；不计改善 |
| capture-review-v2-followups-1 | 3 个真实图追问均拒发；新快照完整。故障追问漏绑记录，HMC/RBD 边界仅凭泛化原则引用具体身份，不能放松这些身份检查 |
| replay-review-v2-final-mixed | 2 个正常样本 + 3 个新捕获失败样本，各重复两次，10/10 完成审核发布。正常样本一次审核，原失败样本一次修订加重新审核 |
| review-v2-final-offline-revalidation.json | 修复脚注标签及保留交付信息后，零模型调用重验上述 10 份最终提案，全部通过；不是新语义成绩 |
| replay-review-v2-release-check | 最终代码同五个样本的单次真实复测，5/5 完成审核发布；结果保存在 run.json，不与前两次重复混算 |

两次固定初稿复测实际调用 22 次，不含未重新生成的 10 份初稿。不能据此声称生产只需 1/3 次调用，也不能与旧整图成本直接比较。各轮均检查固定输入和生成模型参数一致。

## 内容复核：不能宣布整体质量合格

以下是编码智能体依据捕获权威字段的复核，不是领域专家签审，也不把审核模型自报 full 当作独立评分。

| 样本 | 已改善或保持 | 未解决 |
|---|---|---|
| HMC 首问 | 现象、检查采样/钳位器件与记录一致 | 边界/来源重复；通配适用性解释须谨慎 |
| 历史追问 | 明确针脚修复后恢复的排除依据，以及 2 小时无丢帧、计数一致、幅值合限三项结果 | 后段重复；不是通用复测程序 |
| 现场处置追问 | 有电源间歇退出的 MFL 检查、处置、状态字来源 | 仍展开 HUM 邻近故障及 GPP-B 存储高温历史；虽声明不同，不能视为相关历史已经充分回答 |
| HMC→MFL 追问 | 未把邻居报码当同码，区分未确认关联与原文没有 | 仍缺对应 MFL 的权威关联，维修查询目标未全面解决 |
| RBD 能力边界 | 回答结构/成功判据与不能直接给根因/维修结论，引用保持 RBD | 过长；“RBD 不包含某内容”可能把方法职责泛化成文档绝对缺项 |

本批证明受控修订与来源校验能运行，不证明五题都已高质量回答。“真实但不够相关”的记录仍可能被展开，不能只用发布成功率验收。
