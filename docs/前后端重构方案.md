# 前后端重构方案

> 目标：将现有「单文件前端 + 巨型路由后端」重构为标准化的前后端分层架构。
> 前端：React 18 + TypeScript + Vite + Ant Design 5 + SWR + React Router
> 后端：FastAPI + 异步 SQLAlchemy 2.0 + Pydantic v2
> 约束：增量迁移，每阶段可运行可回滚，不破坏现有数据。

---

## 一、现状与痛点

### 1.1 前端现状

| 文件 | 行数 | 问题 |
|---|---|---|
| `static/index.html` | 7106 | 单文件巨型页面，7 个页面靠 `switchPage()` 切换，无组件化、无类型安全、无路由 |
| `static/agent.html` | 2002 | 智能体对话页，同样单文件 |
| `static/gallery.html` | 445 | 图片画廊 |

- 所有逻辑（DOM 操作、fetch、状态、渲染）混杂在 `<script>` 中
- 无构建工具、无模块化、无依赖管理
- 维护成本高：改一个功能要在 7000 行中搜索

### 1.2 后端现状

| 文件 | 行数 | 问题 |
|---|---|---|
| `app/api/routers/documents.py` | 2650 | 路由混入全部业务逻辑（上传、解析、图谱生成、删除、任务管理） |
| `app/storage/postgres_client.py` | - | 裸 psycopg2 单例连接，无 ORM，SQL 散落各处 |
| `app/storage/es_client.py` / `hugegraph_client.py` | - | 基础设施客户端，无 repository 抽象 |

- 无 service 层：业务逻辑直接写在 router
- 无 ORM：SQL 手写，表结构变化需改多处
- 无统一异常处理、统一响应格式
- agent 模块（`app/agent/`）已示范模块化，但同样使用裸 SQL

## 三、后端分层设计

### 3.1 models 层（异步 SQLAlchemy 2.0）

用声明式风格映射**已有表**，表名/列名不变，数据零风险。

```python
# backend/models/base.py
from sqlalchemy.orm import DeclarativeBase

class Base(DeclarativeBase):
    pass
```

```python
# backend/models/document.py
from sqlalchemy import String, Integer, DateTime
from sqlalchemy.orm import Mapped, mapped_column
from .base import Base

class Document(Base):
    __tablename__ = "documents"   # 映射现有表，不重建
    doc_id: Mapped[str] = mapped_column(String(36), primary_key=True)
    file_name: Mapped[str] = mapped_column(String(255))
    kb_id: Mapped[str] = mapped_column(String(36))
    status: Mapped[str] = mapped_column(String(32))
    total_chunks: Mapped[int] = mapped_column(Integer, default=0)
    created_at: Mapped[DateTime] = mapped_column(DateTime)
```

**关键点：**
- 只做映射不迁移表，符合「数据库修改用新表而非改表」的约束
- 表结构变化时，先改现有表 → 再更新模型，或新建模型表

### 3.2 数据库会话（异步）

```python
# backend/core/db.py
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker

DATABASE_URL = "postgresql+asyncpg://user:pass@localhost:5432/knowledge_graph"
engine = create_async_engine(DATABASE_URL, echo=False)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)
```

```python
# backend/api/deps.py
async def get_db():
    async with SessionLocal() as session:
        yield session
```

> **注意**：现有 `postgres_client.py` 是同步 psycopg2。异步化迁移时，`postgres_client` 保持可用，新代码走异步 session，逐步替换。

### 3.3 repository 层（数据访问统一出口）

```python
# backend/repositories/document_repo.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from ..models.document import Document

class DocumentRepository:
    def __init__(self, session: AsyncSession):
        self.session = session

    async def get_by_id(self, doc_id: str) -> Document | None:
        result = await self.session.execute(select(Document).where(Document.doc_id == doc_id))
        return result.scalar_one_or_none()

    async def list_by_kb(self, kb_id: str) -> list[Document]:
        result = await self.session.execute(select(Document).where(Document.kb_id == kb_id))
        return list(result.scalars().all())
```

**同步客户端（ES/HG/MinIO）在异步 service 中的调用方式：**
```python
# backend/repositories/graph_repo.py
import asyncio
from ..storage.hugegraph_client import hugegraph_client

class GraphRepository:
    async def delete_by_doc_id(self, doc_id: str):
        # 同步客户端用 to_thread 包裹，避免阻塞事件循环
        return await asyncio.to_thread(hugegraph_client.delete_vertices_by_doc_id, doc_id)
```

### 3.5 controller 层（路由只做编排）

```python
# backend/api/routers/documents.py
from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession
from ..deps import get_db
from ...services.deletion_service import DeletionService
from ...repositories import DocumentRepository, GraphRepository, CommunityReportRepository

router = APIRouter(prefix="/knowledge-bases", tags=["knowledge-bases"])

@router.delete("/{kb_id}/documents/{doc_id}/graph-data")
async def delete_document_graph_data(kb_id: str, doc_id: str, db: AsyncSession = Depends(get_db)):
    service = DeletionService(
        doc_repo=DocumentRepository(db),
        graph_repo=GraphRepository(),
        community_repo=CommunityReportRepository(),
    )
    return await service.delete_document_graph_data(kb_id, doc_id)
```

### 3.6 统一响应与异常

```python
# backend/core/exceptions.py
class BusinessError(Exception):
    def __init__(self, code: int, message: str):
        self.code = code
        self.message = message

# backend/core/response.py
def ok(data=None, message="success"):
    return {"code": 0, "message": message, "data": data}

def fail(code: int, message: str):
    return {"code": code, "message": message, "data": None}

# main.py 注册全局异常处理器
@app.exception_handler(BusinessError)
async def business_error_handler(request, exc: BusinessError):
    return JSONResponse(status_code=400, content=fail(exc.code, exc.message))
```

### 4.1 service 层（fetch 封装）

```typescript
// src/api/request.ts
const BASE_URL = '/api/v1';

export async function request<T>(path: string, options?: RequestInit): Promise<T> {
  const res = await fetch(`${BASE_URL}${path}`, {
    headers: { 'Content-Type': 'application/json' },
    ...options,
  });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json() as Promise<T>;
}
```

### 4.6 视觉风格：白毛玻璃效果（White Glassmorphism）

> 重构后的前端**整体视觉风格切换为"白色磨砂玻璃"（frosted white glass）**，
> 取代现有的纯色卡片 + 灰底布局。风格基调：轻量、通透、柔和、层次分明。

#### 4.6.1 风格定义

| 设计要素 | 规范 |
|---|---|
| 风格名称 | 白毛玻璃效果（White Glassmorphism / Frosted Glass） |
| 核心手法 | 半透明白色卡片 + `backdrop-filter: blur()` 背景模糊 + 高光细边框 + 柔和投影 |
| 整体气质 | 轻量、通透、留白充足，避免厚重阴影与高饱和撞色 |
| 适用对象 | 全站容器（卡片/弹窗/侧栏/顶栏/表格/搜索框） |

#### 4.6.2 色板与背景

```
背景（body 层）：
  基础渐变   linear-gradient(135deg, #eef2f7 0%, #f8fafc 40%, #e6ecf4 100%)
  氛围光斑   页面四角叠加 2-3 个模糊圆形光斑（径向渐变，蓝/紫低饱和，opacity 0.35）
             —— 光斑是毛玻璃"透出"效果的关键，让玻璃看起来真的在背景之上

玻璃层（白毛玻璃卡片）：
  背景色     rgba(255, 255, 255, 0.55) ~ 0.72
  模糊       backdrop-filter: blur(14px) saturate(160%)
  边框       1px solid rgba(255, 255, 255, 0.65)   （顶部高光）
  阴影       0 8px 32px rgba(31, 45, 78, 0.08)
  圆角       12px ~ 16px

文字层级：
  主文字     #1f2d4e（深蓝灰，正文/标题）
  次文字     #6b7a99（说明/描述）
  弱文字     #9aa7c3（占位/时间戳）
  主色       #667eea（保持与现有渐变主色一致的品牌蓝紫）
  成功/警告/危险  沿用 AntD 语义色（绿 #52c41a / 橙 #fa8c16 / 红 #ff4d4f）

交互态：
  hover      背景透明度提升至 0.85、阴影加深至 0.12、轻微上浮 translateY(-2px)
  active/选中 边框主色 1px + 内阴影 + 背景 0.9
```

#### 4.6.3 AntD 5 主题接入（ConfigProvider + CSS）

```tsx
// src/theme.ts —— 全局主题入口
import { theme } from 'antd';

// 1. 语义 token：颜色、圆角、字体
export const glassToken = {
  colorPrimary: '#667eea',
  colorBgLayout: 'transparent',            // 布局背景交给 body 渐变
  colorBgContainer: 'rgba(255,255,255,0.60)',
  colorBorderSecondary: 'rgba(255,255,255,0.65)',
  borderRadius: 12,
  colorText: '#1f2d4e',
  colorTextSecondary: '#6b7a99',
  fontFamily: "-apple-system, 'PingFang SC', 'Microsoft YaHei', sans-serif",
};

// 2. 覆盖关键组件为玻璃质感
export const glassComponents = {
  Layout: { bodyBg: 'transparent', siderBg: 'rgba(255,255,255,0.55)' },
  Card:   { colorBgContainer: 'rgba(255,255,255,0.60)', boxShadow: '0 8px 32px rgba(31,45,78,0.08)' },
  Modal:  { contentBg: 'rgba(255,255,255,0.72)', borderRadiusLG: 16 },
  Table:  { headerBg: 'rgba(255,255,255,0.50)', rowHoverBg: 'rgba(102,126,234,0.06)' },
  Menu:   { itemBg: 'transparent', itemSelectedBg: 'rgba(102,126,234,0.14)' },
  Input:  { colorBgContainer: 'rgba(255,255,255,0.55)', activeBorderColor: '#667eea' },
};

export default function AppTheme({ children }) {
  return (
    <ConfigProvider theme={{ token: glassToken, components: glassComponents }}>
      {children}
    </ConfigProvider>
  );
}
```

```css
/* src/styles/glass.css —— 全局玻璃基类 */
.glass {
  background: rgba(255, 255, 255, 0.60);
  backdrop-filter: blur(14px) saturate(160%);

  min-height: 100vh;
  background:
    radial-gradient(600px 400px at 8% 10%, rgba(102, 126, 234, 0.18), transparent 60%),
    radial-gradient(700px 500px at 92% 85%, rgba(118, 75, 162, 0.14), transparent 60%),

```

> **backdrop-filter 生效前提**：模糊必须建立在**有内容的背景层**之上。
> body 背景光斑务必保留（不能退化为纯白底），否则毛玻璃与白底视觉上无差异。

#### 4.6.4 关键区域落地映射

| 区域 | 玻璃化方案 |
|---|---|
| 侧边栏（Sider） | 整条 `rgba(255,255,255,0.55)` + blur，菜单选中项主色浅底 |
| 顶栏（Header） | 半透明白 + 底部 1px 高光线，右侧用户/设置区玻璃胶囊 |
| 内容卡片（上传/检索/模型/日志） | 全部 `.glass` 基类，统计数字用主色大字号 |
| 弹窗（Modal / Drawer） | 毛玻璃面板 + 遮罩 `rgba(31,45,78,0.35)`，关闭按钮 hover 圆形高亮 |
| 表格（Table） | 表头半透明、行 hover 主色 6% 底、斑马纹用白色 30% |
| 标签/徽标（Tag / Badge） | 白底 0.7 + 主色 8% 描边，社区报告评分 `⭐` 用渐变胶囊 |
| 搜索框/下拉（Select / AutoComplete） | 半透明底 + 聚焦主色描边，下拉面板玻璃化 |
| 空状态 / 加载占位 | 玻璃占位卡 + 细虚线描边 |
| G6 图谱画布 | 容器玻璃化，但画布本身 `background: transparent`，节点/边样式沿用现有色板 |

#### 4.6.5 动效与可访问性

- 切换/进入过渡：卡片淡入 + 轻微上浮（`opacity 0→1` + `translateY(8px→0)`，200-250ms）
- 弹窗/抽屉：AntD 默认 motion，圆角 16px
- 所有动效遵循 `prefers-reduced-motion: reduce` 时禁用
- 文字与背景对比度保证：正文 #1f2d4e 落在 0.55 白玻璃上对比度 > 4.5:1
- 旧页面（迁移完成前并存期）保持原样式，新页面统一玻璃风，切页时观感差异由迁移完成消除

#### 4.6.6 迁移注意事项（风格部分）

- `antd@5` 通过 `ConfigProvider` token 定制即可，**无需引入额外 UI 库**（不引入 tailwind/mui）
- 旧 index.html 的 `.header` 渐变（#667eea→#764ba2）仅保留为品牌主色来源，不直接复用渐变 header
- G6 图谱节点/边的高亮/dim 三态颜色保留现状（业务语义色，不随风格改）
- 社区报告、思考面板等**信息密度高**的区域，玻璃透明度取 0.72（比普通卡片更实），保证可读性

## 五、部署方案

```
frontend/  --vite build-->  static/  (dist 产物输出到后端 static)
```

```ts
// frontend/vite.config.ts
export default defineConfig({
```

> **注意**：`emptyOutDir: true` 会清空 static。需配置 `publicDir` 保留旧文件（迁移期间旧页面并存），或迁移完成后再启用清空。

## 六、迁移路线图

> 每个阶段独立可运行、可回滚。不搞大爆炸重写。

### 阶段 0：搭建骨架
- 创建 `frontend/` Vite 脚手架（React + TS + AntD 5 + SWR + Router + zustand）
- 创建后端分层目录（services/models/schemas/repositories）
- 验证：空页面能跑，`npm run dev` 代理到 9999

### 阶段 1：后端抽 service（不动行为）
- 将 `documents.py` 业务逻辑抽到 `services/`
- 路由瘦身为编排层
- 验证：现有页面行为不变

### 阶段 2：引入 SQLAlchemy（异步）映射现有表

### 9.2 后端必须保留的机制（红线）

#### A. 解析流水线与状态机

```
uploaded → parsing → indexed → generating_kg → completed（含 failed）
```

- `app/main.py:37-84` 启动恢复：`generating_kg→indexed`、`parsing→uploaded`，并对孤立任务补写 cancelled 日志——**容错基石，不得删**
- TaskManager（`app/core/task_manager.py`）是**纯内存**状态 + SSE 队列，`stream_events` 语义为"先回放历史 logs 再消费队列"

#### B. 线程/并发模型

- FastAPI 全异步路由，所有同步阻塞调用（psycopg2/minio/ES/requests/LLM/networkx/pandas）经 `run_in_executor` 包裹——重构用 `asyncio.to_thread` 等价替换，**必须覆盖全部调用点**
- `llm_semaphore = asyncio.Semaphore(3)`（documents.py:33）并发闸门必须保留

#### C. ID 命名约定（删除级联与跨文档合并依赖）

| 对象 | 约定 |
|---|---|
| ES chunk _id | `{doc_id}_{block_key}`；图片 `{chunk_id}_img_{idx}`；表格 `{chunk_id}_tbl_{idx}` |
| HG 顶点 | `{kb_id}_{doc_id}_{idx}`；边 `{kb_id}_{doc_id}_edge_{idx}`；故障树 `{doc_id}_ft_{img_idx}_v_{idx}` |
| HG 图片文件名 | `img_{safe_section}_{index}_{timestamp}_{uuid8}.png` |
| 社区报告 ES id | **必须 `{kb_id}_{report_id}`**（否则跨知识库互相覆盖，2026-08-12 已踩坑） |
| HG doc_id 多文档 | `doc_id_to_str` 逗号拼接，读回各处 `split(",")` |

#### D. 存储层约束

| 存储 | 约束 |
|---|---|
| PG | psycopg2 **同步单例连接**多线程共享，换 asyncpg 前**不得在并发协程里复用同一连接**；日志表外键被故意移除（留痕设计），不得恢复；`delete_step/is_deleted/image_url/快照列` 等后加列不能丢 |
| ES | 单索引 `knowledge_graph_default` + `kb_id` 字段隔离 + `removed_kwd="N"` 过滤；dense_vector dims=1024 与 embedding 模型维度强绑定；`doc_ids` 必须用 `.keyword` 子字段精确匹配（text 分词会失败） |
| HG | `CUSTOMIZE_STRING` 顶点 id 必须 `_quote_vid` 双引号包裹；weight 转 INT；`*_parts` 可追溯结构（description_parts/keywords_parts/weight_parts）是"删除=精确裁剪"的前提 |
| Mock 降级 | PG/ES/HG 连接失败自动 Mock，保证离线可运行，保留 |

#### E. 删除级联

- `DELETE_STEP_ORDER`（_deletion_helpers.py:11）8 步断点续删 + `documents.delete_step` 列是失败恢复唯一手段
- ES 删除**只删 `knowledge_graph_kwd=chunk`**，社区报告走三级处理（物理删 / content stale / topology stale），与检索侧 `must_not stale_kwd=topology`、content stale 降权 0.7 配套
- 日志留痕三件套：日志表无外键 + kb_name/doc_name 快照列 + DeletionLogger 写库失败内存缓冲

#### F. 模型配置唯一来源

- **模型身份配置只读 `llm_models` 表**（llm_service/embedding/rerank 三处一致），禁 .env/config 回退
- 默认模型语义：`model_type + is_default + is_active LIMIT 1`；`set-default` 后必须 `model_config_service.refresh()` + `llm_service.refresh()` 双刷新
- api_key 一律掩码 `"******"` 返回前端
- 流式必须 `astream`/`httpx.AsyncClient`（不能用同步 requests/for，否则事件循环阻塞）
- rerank 失败降级（返回 None 不中断主流程）

#### G. 图片存储（容器化部署硬约束）

- docker-compose app 服务**必须**设 `IMAGE_STORAGE_DIR=/app/storage/images` 并挂载宿主机 `./app/storage/images`；否则 config 默认解析为镜像内 `/app/app/storage/images`，**容器重建即图片丢失（画廊 404）**
- MinIO 与本地"双写互不影响"，`get_file` 有 /tmp 兜底

#### H. 检索降级链与算法

- embedding 失败自动回退 keyword（es_vector/es_hybrid 均实现）
- RRF 公式 `1/(rrf_k + rank + 1)`，`rrf_k = 60`
- 所有检索带 kb_id 隔离（PG JOIN / ES term / HG properties）

## 十一、存量坑位（重构时顺手修复）

1. **agent `_decide_next` 硬编码 `iteration>=4`**（graph.py:68）与 `max_reflections`（默认 3）不一致，应统一为单一配置源
2. **plan 节点 `maybe_summarize` 计算了但没生效**（plan.py:109-117）：结果未放进节点 return dict，每次超阈值白调一次 LLM——重构时要么真正合并进 messages channel，要么删除
3. **agent `_running_tasks` 按 session_id 单键**（chat_router.py:36）：同一会话并发请求互相覆盖；`/chat/stop` 是空实现，停止依赖前端断开 SSE
4. **compress_session 手工 DELETE checkpoints 表**（chat_router.py:357-363）：与 langgraph 内部表结构强耦合，升级 langgraph 版本可能失败（有 try/except 兜底但会残留）
5. **删除会话不删 checkpoint**：`DELETE /session/{id}` 只删 agent_sessions/messages，LangGraph checkpoint 残留（thread_id 隔离防串话，但长期是脏数据）
6. **registry.get_tool_nodes 与 graph.py 内联注册重复**：二选一，避免两处维护
7. **store 未初始化时长期记忆静默失效**：memory.py 对 `store is None` 直接返回空，无告警，排查困难
8. **G6 边粒子动画定时器/监听从不清理**（index.html 5953-6033）：React 卸载必须清理
9. **agent 停止后 500ms 延迟刷新会话**（agent.html 1650）依赖 `setTimeout`，React 中需用 effect 清理
10. **旧 index.html 的 `prompt()`/`confirm()`/`alert()` 交互**：迁移到 AntD Modal/message 时注意保持"输入确定"等语义
