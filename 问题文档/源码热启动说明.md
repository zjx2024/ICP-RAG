# ICP_RAG 新一代版本 · 源码热启动说明

> 项目路径：`/home/kdfy/test_code/ICP_RAG`
> 开发模式：前后端均使用源码启动（热更新），基础设施用 Docker Compose（独立项目名 `-p icp`）
> 与老项目 `RAG_Agent_v1.0`（9999/5173）完全隔离，可同时运行

## 启动步骤

### 1. 启动基础设施（只需一次，容器在跑可跳过）

```bash
cd /home/kdfy/test_code/ICP_RAG
./start.sh
```

说明：`start.sh` 默认只启动 postgres/elasticsearch/minio/hugegraph/hubble 五个容器，
**不启动容器版 app**（开发走源码热启动，避免占用 19999 端口）。

### 2. 后端热启动（端口 19999）

```bash
cd /home/kdfy/test_code/ICP_RAG
./start_server.sh
```

- 修改 `backend/` 下代码自动重载，无需手动重启
- 脚本已自动导出新端口环境变量：`ES_PORT=9201`、`POSTGRES_PORT=5433`、
  `MINIO_ENDPOINT=localhost:9002`、`HUGEGRAPH_PORT=8082`、`SERVER_PORT=19999`
- `--reload-dir backend`：只监听源码目录，避免扫描 `volumes/`（root 属主不可读）导致 reload 守护崩溃

### 3. 前端热启动（端口 5174）

```bash
cd /home/kdfy/test_code/ICP_RAG/frontend
source ~/.nvm/nvm.sh && nvm use v24.11.1   # 必须用 node 24（系统 node 为 v12，vite 5 无法运行）
npm run dev
```

- 修改 `frontend/src/` 下代码浏览器即时热更新
- vite 代理 `/api`、`/images` 到后端 `http://localhost:19999`

### 4. 访问

- 前端页面：`http://localhost:5174/static/dist/`
- 后端接口：`http://localhost:19999`（Swagger 文档 `/docs`）

## 停止

```bash
cd /home/kdfy/test_code/ICP_RAG
./stop.sh    # 只停基础设施容器（数据卷保留）
```

- 后端 / 前端按 `Ctrl+C` 停止即可
- 数据持久化在 `./volumes/`，下次 `./start.sh` 直接恢复

## 注意事项

1. **node 版本**：前端必须使用 nvm 的 node v24.11.1（`source ~/.nvm/nvm.sh && nvm use v24.11.1`），系统 `/usr/bin/node` 是 v12 无法跑 vite 5。
2. **首次使用**：新库为空，需先在「模型管理」页配置 LLM / Embedding / Rerank 模型（从 `llm_models` 表选择）。
3. **不要修改 `volumes/` 目录属主**：postgres 卷属主为 uid 999、ES 卷为 uid 1000，删除/重建卷后如遇 ES 权限报错
   （`AccessDeniedException: node.lock`），用 `docker run --rm -v $(pwd)/volumes/es:/data alpine chown -R 1000:1000 /data` 修复。
4. **容器版 app（可选）**：如需 Docker 部署形态，先 `cd frontend && npm run build` 产出 `static/dist`，
   再执行 `./start.sh up -d app`（监听宿主机 19999；与热启动二选一，勿同时运行）。
5. **历史遗留容器**：机器上可能存在旧的 `icp-postgres`（postgres:16）等停止容器，本项目通过 `-p icp` +
   不写死 `container_name`（容器名为 `icp-<service>-1`）避开重名，请勿删除该历史容器以免误删旧数据。
